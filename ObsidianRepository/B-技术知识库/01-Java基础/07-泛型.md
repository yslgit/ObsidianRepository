# Java 泛型

## 📖 本章导读

### 学习目标
通过本章学习,你将掌握:
- ✅ 泛型的基本语法(类/接口/方法)
- ✅ 类型擦除机制和桥方法
- ✅ 通配符(? extends / ? super)的使用场景
- ✅ PECS原则(Producer Extends, Consumer Super)
- ✅ 泛型的限制和常见陷阱
- ✅ 反射获取泛型信息

### 核心概念
**泛型**提供编译期类型安全,避免运行时ClassCastException。Java泛型通过**类型擦除**实现,运行时不保留泛型信息。**通配符**解决泛型的不变性问题,**PECS原则**指导通配符选择。

### 知识地图
```
泛型
├── 基础语法
│   ├── 泛型类: class Box<T>
│   ├── 泛型接口: interface Comparable<T>
│   └── 泛型方法: <T> T getMiddle(T... args)
├── 类型擦除
│   ├── 擦除机制: T→Object或边界类型
│   ├── 桥方法: 保持多态性
│   └── 影响: instanceof/new T[]/new T()不可用
├── 通配符
│   ├── 上界: ? extends T (Producer)
│   ├── 下界: ? super T (Consumer)
│   └── 无界: ? (只读,Object)
├── PECS原则
│   ├── Producer Extends: 只读场景
│   ├── Consumer Super: 只写场景
│   └── 既是P又是C: 不用通配符
├── 泛型限制
│   ├── 不能创建泛型数组
│   ├── 不能实例化类型参数
│   ├── 不能捕获泛型异常
│   └── 静态上下文不能使用类型参数
└── 高级特性
    ├── 递归类型绑定: <T extends Comparable<T>>
    ├── 多个边界: <T extends A & B>
    └── TypeToken: 绕过类型擦除
```

### 常见误区
❌ **误区1**: `List<Object> list = new ArrayList<String>();`
✅ **真相**: 泛型是不变的,List<String>不是List<Object>的子类

❌ **误区2**: 运行时可以判断`obj instanceof List<String>`
✅ **真相**: 类型擦除后只剩List,无法判断具体类型参数

❌ **误区3**: `? extends T`可以写入T类型对象
✅ **真相**: ? extends T是Producer,只能读取,不能写入(除null)

### 实战建议
1. **API设计**: 优先使用泛型,提高类型安全性
2. **通配符选择**: 遵循PECS原则(Producer Extends, Consumer Super)
3. **集合返回**: 返回`Collection<? extends T>`提高灵活性
4. **避免裸类型**: 始终指定类型参数,避免warning
5. **泛型数组**: 用`List<T>`替代`T[]`,或用反射创建
6. **工具方法**: 泛型方法比泛型类更灵活
7. **TypeReference**: Jackson等库用TypeReference保留泛型信息

## 1. 泛型基础

### 1.1 为什么需要泛型

```java
// 没有泛型之前（JDK 5 之前）：
List list = new ArrayList();
list.add("hello");
list.add(123);           // 可以添加任何类型
String s = (String) list.get(0);  // 必须强转
Integer i = (Integer) list.get(1);

// 问题：类型不安全，运行时可能 ClassCastException
// String s = (String) list.get(1);  // ClassCastException！

// 使用泛型后（JDK 5+）：
List<String> list = new ArrayList<>();  // JDK 7+ 菱形推断 <>
list.add("hello");
// list.add(123);  // ❌ 编译错误！类型安全
String s = list.get(0);  // 无需强转
```

### 1.2 泛型类

```java
// 定义一个泛型类
public class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}

// 使用
Box<String> stringBox = new Box<>("hello");     // T = String
Box<Integer> intBox = new Box<>(123);            // T = Integer
String s = stringBox.getValue();                 // 类型安全，无需强转

// 多类型参数
public class Pair<K, V> {
    private K key;
    private V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

Pair<String, Integer> pair = new Pair<>("age", 25);
```

### 1.3 泛型接口

```java
// 泛型接口
public interface Comparable<T> {
    int compareTo(T o);
}

// 实现方式 1：指定具体类型
public class String implements Comparable<String> {
    @Override
    public int compareTo(String o) { ... }
}

// 实现方式 2：保持泛型
public class Result<T> implements Comparable<T> {
    @Override
    public int compareTo(T o) { ... }
}
```

### 1.4 泛型方法

```java
// 泛型方法（类型参数在返回值之前、修饰符之后声明）
public class Utility {
    // 静态泛型方法
    public static <T> T getMiddle(T... args) {
        return args[args.length / 2];
    }

    // 非静态泛型方法
    public <T> void printArray(T[] array) {
        for (T elem : array) {
            System.out.println(elem);
        }
    }
}

// 类型推断
String middle = Utility.getMiddle("a", "b", "c");  // T 被推断为 String
Integer mid = Utility.<Integer>getMiddle(1, 2, 3); // 显式指定类型

// 泛型构造器
public class Person {
    public <T> Person(T name) {
        // T 只是构造器的类型参数，与类无关
        System.out.println(name);
    }
}
// 创建时类型推断
Person p = new Person("Alice");  // <String> 被推断
```

## 2. 类型擦除（Type Erasure）

### 2.1 擦除的机制

```java
// Java 的泛型是编译期的假象——运行时没有泛型信息！
// 编译器在编译后擦除类型参数，替换为边界类型（未指定边界则为 Object）

// 源代码：
public class Box<T> {
    private T value;
    public T getValue() { return value; }
    public void setValue(T value) { this.value = value; }
}

// 编译后擦除为（等价代码）：
public class Box {
    private Object value;       // T → Object
    public Object getValue() { return value; }
    public void setValue(Object value) { this.value = value; }
}

// 有边界时：
public class Box<T extends Number> {
    private T value;
}
// 擦除为：
public class Box {
    private Number value;  // T → Number（边界类型）
}
```

### 2.2 桥方法（Bridge Method）

```java
// 类型擦除可能导致多态失效，编译器通过桥方法解决

public class Parent {
    public Object getValue() { return "parent"; }
}

public class Child extends Parent {
    @Override
    public String getValue() { return "child"; }  // 协变返回类型
}

// 编译后 Child 类实际包含两个方法：
// 1. public String getValue()  ← 用户写的方法
// 2. public Object getValue()  ← 编译器生成的桥方法
//    {
//        return this.getValue();  // 调用 String 版本
//    }

// 验证桥方法的存在：
for (Method m : Child.class.getMethods()) {
    if (m.getName().equals("getValue")) {
        System.out.println(m + " isBridge=" + m.isBridge());
    }
}
```

### 2.3 擦除的影响

```java
// 1. 不能使用 instanceof 检查泛型类型
Box<String> box = new Box<>();
// if (box instanceof Box<String>) { }  // ❌ 编译错误
if (box instanceof Box) { }               // ✅ 裸类型检查（warning）

// 2. 不能创建泛型数组
// Box<String>[] arr = new Box<String>[10];  // ❌ 编译错误
Box<String>[] arr = (Box<String>[]) new Box[10];  // ✅ 绕过后有 warning

// 3. 不能创建类型参数的实例
public <T> T create() {
    // return new T();  // ❌ 编译错误
    return null;
}

// 4. 不能创建类型参数的数组
public <T> T[] createArray(int size) {
    // return new T[size];  // ❌ 编译错误
    return (T[]) new Object[size];  // ✅ 绕过后有 warning
}

// 5. 静态上下文中不能引用类型参数
public class Box<T> {
    // private static T value;  // ❌ 编译错误
    // public static void print(T t) { }  // ❌ 编译错误
}
```

## 3. 通配符（Wildcards）

### 3.1 上界通配符（extends）

```java
// ? extends T：可以读取 T 类型（Producer）
// 不能写入（除了 null）

public void process(List<? extends Number> list) {
    Number n = list.get(0);  // ✅ 读取为 Number
    // list.add(42);          // ❌ 编译错误！不能添加 Integer
    // list.add(3.14);        // ❌ 编译错误！不能添加 Double
    list.add(null);          // ✅ 只能添加 null
}

// 为什么不能写入？
// List<? extends Number> 可能是 List<Integer>、List<Double> 等
// 编译器无法确定具体类型，因此禁止写入（类型安全）

// 适用场景：只读访问（Producer）
public double sumOfList(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) {
        sum += n.doubleValue();
    }
    return sum;
}
```

### 3.2 下界通配符（super）

```java
// ? super T：可以写入 T 类型（Consumer）
// 读取只能得到 Object

public void addNumbers(List<? super Integer> list) {
    list.add(42);           // ✅ 可以添加 Integer
    list.add(100);          // ✅ 可以添加 Integer
    // Integer i = list.get(0);  // ❌ 编译错误！
    Object obj = list.get(0);   // ✅ 只能读取为 Object
}

// 为什么读取受限？
// List<? super Integer> 可能是 List<Integer>、List<Number>、List<Object>
// 编译器只能确定最小类型为 Object

// 适用场景：只写访问（Consumer）
public void fillWithOnes(List<? super Integer> list) {
    for (int i = 0; i < list.size(); i++) {
        list.set(i, 1);
    }
}
```

### 3.3 无界通配符（?）

```java
// ?：表示未知类型
// 等价于 ? extends Object

public void printList(List<?> list) {
    for (Object elem : list) {
        System.out.println(elem);
    }
    // list.add("hello");  // ❌ 只能添加 null
}

// 何时使用无界通配符：
// 1. 方法只使用 Object 提供的功能
// 2. 泛型类型参数不相关的方法（如 size()、clear()）
```

### 3.4 PECS（Producer Extends, Consumer Super）

```java
// 原则：Producer Extends, Consumer Super

// 如果参数是生产者（提供数据），使用 ? extends T
// 如果参数是消费者（接收数据），使用 ? super T

// 示例：Collections.copy
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    // src 是生产者（读取），使用 extends
    // dest 是消费者（写入），使用 super
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}

// 示例：Collections.sort
public static <T extends Comparable<? super T>> void sort(List<T> list) {
    // T 需要实现 Comparable
    // Comparable<? super T> 允许 T 的父类实现 Comparable
}

// 示例：Optional 的 orElseGet
public T orElseGet(Supplier<? extends T> supplier) {
    // supplier 是生产者，使用 extends
}
```

## 4. 类型边界（Type Bounds）

```java
// 单边界
public class Box<T extends Number> { }
// 只能使用 Number 及其子类

// 多边界（必须用 & 连接，类在第一个，接口在后）
public class Container<T extends Comparable<T> & Serializable> {
    // T 必须同时实现 Comparable 和 Serializable
}

// 边界中的自引用
// 枚举的声明：
public abstract class Enum<E extends Enum<E>> { }
// 这确保：class Color extends Enum<Color> { }

// 递归类型边界
public <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}
// 要求 T 必须可以与自己比较
```

## 5. 类型推断（Type Inference）

```java
// JDK 7：菱形运算符 <>
Box<String> box = new Box<>();            // 编译器从左侧推断

// JDK 8：目标类型推断（Lambda + 泛型）
List<String> list = Collections.emptyList();  // 自动推断为 List<String>

// JDK 10：局部变量类型推断（var）
var list = new ArrayList<String>();       // list 推断为 ArrayList<String>
var pair = new Pair<>("key", 123);       // Pair<String, Integer>

// 注意：var 只能用于局部变量，不能用于字段、方法参数、返回类型
```

## 6. 泛型限制与局限性

```java
// 1. 不能使用基本类型
// Box<int> box;   // ❌ 编译错误
Box<Integer> box;    // ✅ 必须使用包装类

// 2. 运行时类型检查受限
if (box instanceof Box<String>) { }  // ❌ 编译错误
if (box instanceof Box<?>) { }       // ✅ 无界通配符

// 3. 不能用于异常
// class MyException<T> extends Exception { }  // ❌ 编译错误

// 4. 参数化类型不能重载
// public void process(List<String> list) { }
// public void process(List<Integer> list) { }  // ❌ 擦除后相同签名

// 5. 不能直接创建泛型数组
// T[] arr = new T[10];  // ❌

// 6. 类型参数不能用于静态上下文
public class Generic<T> {
    // private static T instance;  // ❌
}

// 7. 不能使用 instanceof 判断参数化类型
// if (obj instanceof List<String>) { }  // ❌
```

## 7. 泛型与反射

```java
// 获取泛型信息（少数情况下运行时可以获取——通过父类）

// ParameterizedType 保留了泛型信息
public abstract class TypeToken<T> {
    private final Type type;

    @SuppressWarnings("unchecked")
    protected TypeToken() {
        // 通过父类获取参数化类型
        Type superClass = getClass().getGenericSuperclass();
        if (superClass instanceof ParameterizedType) {
            this.type = ((ParameterizedType) superClass).getActualTypeArguments()[0];
        } else {
            throw new RuntimeException("Missing type parameter");
        }
    }

    public Type getType() { return type; }
}

// 使用 TypeToken 模式（类似 Gson 的实现）
TypeToken<List<String>> token = new TypeToken<List<String>>() { };
// 运行时保留了 List<String> 的信息

// 获取方法或字段的泛型信息
Field field = Pair.class.getDeclaredField("key");
Type genericType = field.getGenericType();    // TypeVariable K
Type actualType = field.getType();            // Object（擦除后）
```

## 8. 协变、逆变与不变

```java
// Java 中泛型是不变（Invariant）的：
// 即使 A 是 B 的子类型，List<A> 也不是 List<B> 的子类型
// List<B> 也不是 List<A> 的子类型

class Animal { }
class Dog extends Animal { }

// 不变
List<Animal> list1 = new ArrayList<>();
List<Dog> list2 = new ArrayList<>();
// list1 = list2;  // ❌ 编译错误（泛型不变）
// list2 = list1;  // ❌ 编译错误（泛型不变）

// 协变（通过 ? extends）
List<? extends Animal> covariant = new ArrayList<Dog>();  // ✅
// covariant.add(new Dog());  // ❌ 不能添加（除了 null）
Animal a = covariant.get(0);  // ✅ 读取安全

// 逆变（通过 ? super）
List<? super Dog> contravariant = new ArrayList<Animal>();  // ✅
contravariant.add(new Dog());     // ✅ 可以添加 Dog
// Animal a = contravariant.get(0);  // ❌ 只能得到 Object

// 协变与逆变的记忆：
// 协变（extends）：读取安全，写入不安全（Producer → 只读）
// 逆变（super）： 写入安全，读取不安全（Consumer → 只写）
```

## 9. 常见面试题

### Q1: Java 的泛型是如何实现的？
```java
// 通过类型擦除（Type Erasure）实现
// 编译时检查类型安全，运行时擦除泛型信息
// 1. 编译器检查类型参数是否在边界内
// 2. 插入必要的强制转换
// 3. 生成桥方法保持多态

// 这称为"伪泛型"——在字节码层面与不用泛型相同
// 对比 C#：真正的泛型（运行时可获取类型信息）
```

### Q2: `List<Object>` 和 `List<?>` 的区别？
```java
// List<Object>：可以添加任何对象
// List<?>：不能添加元素（除了 null）
// 
// List<Object> 是具体的参数化类型
// List<?> 是通配符，表示未知类型

List<Object> objList = new ArrayList<>();
objList.add("hello");           // ✅
objList.add(123);               // ✅

List<?> wildList = new ArrayList<String>();
// wildList.add("hello");       // ❌ 编译错误
Object o = wildList.get(0);     // ✅ 只读
```

### Q3: 如何创建泛型数组？
```java
// ❌ 直接创建
// List<String>[] arr = new List<String>[5];  // ❌

// ✅ 绕过的几种方式：
// 1. 通配符数组
List<?>[] arr = new List<?>[5];

// 2. 强制转换（有 warning）
List<String>[] arr = (List<String>[]) new List[5];

// 3. 反射
List<String>[] arr = (List<String>[]) Array.newInstance(List.class, 5);
```

### Q4: `? super T` 的理解？
```java
// ? super T：类型的下界是 T
// 接受的类型必须是 T 或 T 的父类

// Collections.addAll 的签名：
public static <T> boolean addAll(Collection<? super T> c, T... elements) {
    // c 是消费者：接受 T 类型的元素
    // 所以使用 ? super T
}
```

### Q5: 泛型方法的类型推断？
```java
// 类型推断：编译器根据上下文推断类型参数

// 1. 从参数推断
public static <T> T identity(T x) { return x; }
String s = identity("hello");  // T 推断为 String

// 2. 从目标类型推断
List<String> list = Collections.emptyList();  // 返回 List<T>，T 推断为 String

// 3. 链式调用中的推断问题
// ❌ 需要显式类型见证
// Collections.emptyList().add("hello");  // 编译错误（T 无法推断）

// ✅ 显式指定
Collections.<String>emptyList().add("hello");
```

### Q6: 什么是堆污染（Heap Pollution）？
```java
// 堆污染：泛型类型不一致的对象被赋值给泛型变量
// 导致运行时 ClassCastException

// 堆污染的常见来源：
// 1. 原始类型与参数化类型混用
List raw = new ArrayList<String>();   // 原始类型
List<Integer> intList = raw;          // 堆污染！
intList.add("hello");                 // 隐藏的危险！

// 2. 可变参数（Varargs）
@SafeVarargs  // 当方法不会修改数组元素时使用
public static <T> void safeMethod(T... args) { }

// 不加 @SafeVarargs 时，编译器警告
public static <T> void unsafeMethod(T... args) {
    Object[] objArr = args;  // 堆污染！
    objArr[0] = "hello";     // 污染了 T[]
}
```

## 10. 最佳实践

1. **优先使用泛型**：类型安全，消除强制转换
2. **使用菱形运算符 `<>`**：JDK 7+ 编译器自动推断
3. **使用 PECS 原则**：`? extends` 生产者，`? super` 消费者
4. **避免原始类型**：`List` 应改为 `List<T>` 或 `List<?>`
5. **@SafeVarargs 谨慎使用**：仅当方法不修改数组内容时
6. **静态方法独立声明类型参数**：`public static <T> void method(T t)`
7. **使用通配符让 API 更灵活**：`List<? extends Number>` 比 `List<Number>` 灵活
8. **类型边界使 API 更强大**：`<T extends Comparable<T>>`
9. **避免在异常中使用泛型**：语法不支持
10. **var 与泛型结合**：`var list = new ArrayList<String>();`
