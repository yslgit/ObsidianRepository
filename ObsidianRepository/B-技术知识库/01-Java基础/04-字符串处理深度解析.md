### 核心概念
**String**是Java中最常用的类,理解其不可变性、常量池和拼接优化对于编写高效代码至关重要。**StringBuilder**用于可变字符串操作,**StringBuffer**提供线程安全版本。

### 知识地图
```
字符串处理
├── String类
│   ├── 不可变性: final class + final byte[]/char[]
│   ├── 常量池: 字面量自动入池,intern()手动入池
│   ├── 拼接优化: 编译期常量折叠,JDK 9+ invokedynamic
│   └── Compact Strings: JDK 9+ Latin-1优化
├── 可变字符串
│   ├── StringBuilder: 单线程,高性能
│   ├── StringBuffer: 多线程,synchronized
│   └── 扩容策略: 2倍+2
├── 常用操作
│   ├── 查找: indexOf, lastIndexOf, contains
│   ├── 截取: substring, split, trim
│   ├── 转换: toUpperCase, toLowerCase, replace
│   └── 比较: equals, compareTo, startsWith
├── 格式化
│   ├── String.format: printf风格
│   ├── MessageFormat: 占位符替换
│   └── DecimalFormat: 数字格式化
└── 正则表达式
    ├── Pattern & Matcher
    ├── 常用元字符: ., *, +, ?, ^, $
    └── 分组与捕获
```

### 常见误区
❌ **误区1**: `String s = new String("hello");` 创建1个对象
✅ **真相**: 创建2个对象(堆中1个+常量池中1个),应该直接用`"hello"`

❌ **误区2**: 循环中使用`+=`拼接字符串
✅ **真相**: 每次循环创建新StringBuilder,应显式使用StringBuilder

❌ **误区3**: `s.substring()`会复制字符数组
✅ **真相**: JDK 6之前共享底层数组(内存泄漏风险),JDK 7+复制新数组

### 实战建议
1. **固定字符串**: 直接用String字面量(自动入池)
2. **大量拼接**: 单线程用StringBuilder,多线程用StringBuffer
3. **预分配容量**: `new StringBuilder(expectedSize)`避免多次扩容
4. **JDK版本**: JDK 9+使用Compact Strings,英文场景内存减半
5. **intern谨慎**: 仅在字符串重复率极高时使用,避免常量池过大
6. **正则性能**: 频繁使用的Pattern应缓存,避免重复编译

## 1. String 类核心原理

### 1.1 String 的不可变性

```java
public final class String
    implements java.io.Serializable, Comparable<String>, CharSequence {
    // JDK 8 及以前：用 char[] 存储
    private final char value[];

    // JDK 9+：用 byte[] + coder（LATIN1 vs UTF16）
    private final byte[] value;
    private final byte coder;  // LATIN1=0, UTF16=1

    // 所有字段都是 final 的
}
```

**不可变性的设计意图：**
```
1. 字符串常量池（String Pool）复用：不可变才能安全共享
2. 哈希缓存：String 缓存 hashCode，不可变才能安全缓存
3. 线程安全：不可变对象天然线程安全
4. 类加载机制：类名使用 String，不可变保证安全
```

**不可变性的错觉：**
```java
String s = "hello";
s = s + " world";  // 这不是修改，是创建新对象！
// 原来的 "hello" 仍然存在（可能被 GC）
```

### 1.2 字符串常量池（String Pool）

```java
// 字符串常量池是 JVM 方法区中的一块特殊区域
// JDK 7+ 移到堆中（方法区空间有限）

// 字面量：自动入池
String s1 = "hello";     // 从常量池获取
String s2 = "hello";     // 复用常量池中的引用
System.out.println(s1 == s2);  // true（同一引用）

// new String：每次都创建新对象
String s3 = new String("hello");  // 堆中新对象
System.out.println(s1 == s3);     // false（不同引用）
System.out.println(s1.equals(s3)); // true（内容相同）

// intern()：手动入池
String s4 = new String("hello");
String s5 = s4.intern();  // 返回常量池中的引用
System.out.println(s1 == s5);  // true（与常量池相同）
```

**intern() 的内部机制：**
```java
// String.intern() 是 native 方法
// 如果常量池中已有相同内容的字符串，返回池中引用
// 否则将当前字符串加入常量池并返回引用

// JDK 7+ 的实现变化：
// JDK 6 及以前：常量池在方法区（永久代），intern 复制对象
// JDK 7+：常量池在堆中，intern 只存引用（如果字符串已存在堆中）

// 经典面试题：
String s1 = new String("1") + new String("2");
s1.intern();               // JDK 7+：将 s1 的引用放入常量池
String s2 = "12";
System.out.println(s1 == s2);  // JDK 6: false, JDK 7+: true
// JDK 6 intern 复制对象到永久代，与堆中的 s1 不同
// JDK 7+ intern 只存引用，s1 和 s2 指向同一个对象
```

### 1.3 字符串拼接的编译优化

```java
// 1. 常量折叠（编译期优化）
String s1 = "hello" + " world";  // 编译为 "hello world"
String s2 = "hello world";
System.out.println(s1 == s2);    // true（同一个常量池对象）

// 常量折叠条件：拼接双方都必须是编译时常量
final String c = "hello";        // final + 字面量 = 编译时常量
String s3 = c + " world";        // 编译为 "hello world"

// 2. 非字符串常量拼接
String s4 = "hello";
String s5 = s4 + " world";      // 编译为 StringBuilder.append
// JDK 5-8：StringBuilder
// JDK 9+：invokedynamic + StringConcatFactory（延迟策略）

// 3. 多步拼接的性能差异
String a = "a";
String b = "b";
String c = "c";

// ❌ 慢：每次 + 都创建新 StringBuilder
String result = a + b + c;
// 编译为：
// StringBuilder tmp = new StringBuilder();
// tmp.append(a).append(b).append(c);
// String result = tmp.toString();

// ❌ 更慢：循环中拼接
String s = "";
for (int i = 0; i < 1000; i++) {
    s += i;  // 每次循环创建新 StringBuilder + 新 String
    // O(n²) 复杂度！
}

// ✅ 好：显式使用 StringBuilder
StringBuilder sb = new StringBuilder(1000);  // 预分配容量
for (int i = 0; i < 1000; i++) {
    sb.append(i);
}
String result = sb.toString();  // O(n) 复杂度
```

### 1.4 JDK 9+ 的 Compact Strings

```java
// JDK 9 引入 Compact Strings（JEP 254）
// 如果字符串所有字符都在 Latin-1 范围内（0x00~0xFF），
// 使用 1 字节/字符存储（byte[]），否则使用 2 字节/字符（byte[] + UTF16 编码）

// 好处：大多数字符串是 Latin-1（英文、数字、常见符号），内存减半

// 内部实现：
// String 类的 coder 字段：
// static final byte LATIN1 = 0;
// static final byte UTF16  = 1;

// 查看字符串是否支持 Latin-1（反射，仅供参考）：
// java.lang.String coder 字段

// 影响：
// - 大多数应用场景内存占用减少 50%
// - 性能略有提升（内存带宽占用减半）
// - charAt() 在 Latin-1 模式不做编码转换
```

## 2. StringBuilder 与 StringBuffer

### 2.1 三者的对比

| 特性 | String | StringBuilder | StringBuffer |
|:---|:---|:---|:---|
| 可变性 | 不可变 | 可变 | 可变 |
| 线程安全 | 安全（不可变） | 不安全 | 安全（synchronized） |
| 性能 | 拼接慢 | 快 | 较慢（同步开销） |
| 使用场景 | 固定字符串 | 单线程大量拼接 | 多线程共享 |

### 2.2 StringBuilder 源码分析

```java
// 核心实现
public final class StringBuilder {
    // 继承 AbstractStringBuilder
    char[] value;      // 存储字符的数组
    int count;         // 已使用的字符数

    // 默认容量 16
    public StringBuilder() {
        super(16);
    }

    // 扩容机制
    public StringBuilder append(String str) {
        super.append(str);  // 调用 AbstractStringBuilder.append
        return this;
    }
}

// AbstractStringBuilder.append()
public AbstractStringBuilder append(String str) {
    if (str == null) return appendNull();
    int len = str.length();
    ensureCapacityInternal(count + len);  // 确保容量
    str.getChars(0, len, value, count);   // 复制字符
    count += len;
    return this;
}

// 扩容策略：2 倍 + 2
private void ensureCapacityInternal(int minimumCapacity) {
    if (minimumCapacity - value.length > 0) {
        // 新容量 = 旧容量 * 2 + 2
        value = Arrays.copyOf(value, newCapacity(minimumCapacity));
    }
}

private int newCapacity(int minCapacity) {
    int newCapacity = (value.length << 1) + 2;  // 2 倍 + 2
    if (newCapacity - minCapacity < 0) {
        newCapacity = minCapacity;
    }
    return (newCapacity > 0) ? newCapacity : Integer.MAX_VALUE;
}
```

### 2.3 容量预分配优化

```java
// StringBuilder 不预设容量时的性能问题：
StringBuilder sb = new StringBuilder();  // 默认 16

// 追加 1000 次：
// 16 → 34 → 70 → 142 → 286 → 574 → 1150（扩容 6 次！）
// 每次扩容：创建新数组 + 复制旧数据（O(n)）

// ✅ 优化：预设容量
StringBuilder sb = new StringBuilder(1000);  // 预先分配 1000
// 不需要扩容，性能更好

// 精确估算容量：
// 已知要拼接 100 个字符串，每个平均 10 字符
StringBuilder sb = new StringBuilder(100 * 10 + 16);  // 预留余量
```

## 3. String 常用方法详解

### 3.1 字符串判断与比较

```java
String s = "Hello World";

// 相等性
s.equals("hello world");       // false（大小写敏感）
s.equalsIgnoreCase("hello world");  // true

// 包含判断
s.contains("World");           // true
s.startsWith("Hello");         // true
s.endsWith("World");           // true
s.isEmpty();                   // false
s.isBlank();                   // false（JDK 11+，空白判断）

// 比较
s.compareTo("Hello");          // 6（字典序比较）
s.compareToIgnoreCase("hello World");  // 0
```

**compareTo 的实现原理：**
```java
// 逐字符比较 Unicode 值
// 返回第一个不同字符的差值（char1 - char2）
// 如果前 n 个字符都相同，返回长度差

"abc".compareTo("abc");    // 0
"abc".compareTo("abd");    // -1（'c' - 'd' = -1）
"abc".compareTo("ab");     // 1（长度差：3 - 2 = 1）
```

### 3.2 字符串查找

```java
String s = "Hello World, Hello Java";

// 字符查找
s.indexOf('o');             // 4（第一个）
s.indexOf('o', 5);         // 7（从索引 5 开始找）
s.lastIndexOf('o');        // 18（最后一个）
s.lastIndexOf('o', 10);    // 7（在索引 10 之前找）

// 字符串查找
s.indexOf("Hello");         // 0
s.lastIndexOf("Hello");     // 13

// 判空相关
"".isEmpty();               // true（长度为 0）
"  ".isEmpty();             // false（有空格）
"  ".isBlank();             // true（JDK 11+，仅空白）
"".length();                // 0
```

### 3.3 字符串截取与拼接

```java
String s = "Hello World";

// 子串（JDK 7+：创建新字符串，不共享底层数组）
s.substring(6);             // "World"
s.substring(0, 5);          // "Hello"
s.subSequence(0, 5);        // CharSequence 接口返回

// 拼接与分隔
s.concat("!!");             // "Hello World!!"
String.join(", ", "a", "b", "c");  // "a, b, c"
String.join("-", "2024", "01", "01");  // "2024-01-01"

// 重复（JDK 11+）
"Hi".repeat(3);             // "HiHiHi"
```

**JDK 7 的 substring 变化：**
```java
// JDK 6：substring 共享原字符串的 char[]
// 优点：速度快，不额外占用内存
// 缺点：大字符串的小子串会阻止大字符串 GC

// JDK 7+：substring 创建新 char[]
// 优点：子串可独立 GC
// 缺点：额外的复制开销
```

### 3.4 字符串替换

```java
String s = "Hello World Hello";

// 字符替换
s.replace('l', 'L');        // "HeLLo WorLd HeLLo"

// 字符串替换
s.replace("Hello", "Hi");   // "Hi World Hi"

// 正则替换
s.replaceAll("\\s", "_");   // "Hello_World_Hello"（正则匹配）
s.replaceFirst("\\s", "_"); // "Hello_World Hello"（仅第一个）
```

**replace vs replaceAll vs replaceFirst：**
```java
// replace(CharSequence, CharSequence)：纯字符串替换，不涉及正则
// replaceAll(String, String)：正则匹配替换
// replaceFirst(String, String)：正则匹配替换第一个

"Hello123".replace("\\d", "");    // "Hello123"（没有数字被替换，因为不是正则）
"Hello123".replaceAll("\\d", ""); // "Hello"（\d 作为正则匹配数字）

// 性能：replace 比 replaceAll 快（没有正则编译开销）
```

### 3.5 字符串分割与合并

```java
// split 使用正则表达式分割
String s = "a,b,c,d";
String[] parts = s.split(",");         // ["a", "b", "c", "d"]
String[] parts2 = s.split(",", 3);     // ["a", "b", "c,d"]（limit 限制）

// 尾随空字符串的处理
"a,b,".split(",");           // ["a", "b"]（尾随空串被省略！）
"a,b,".split(",", -1);      // ["a", "b", ""]（负数 limit 保留所有）
"a,,b".split(",");           // ["a", "", "b"]

// JDK 8+：String.join
String joined = String.join(",", "a", "b", "c");  // "a,b,c"
// 或使用 Collectors.joining
Stream.of("a", "b", "c").collect(Collectors.joining(","));  // "a,b,c"

// StringTokenizer（遗留类，不推荐使用）
// 功能弱于 split 和 Scanner
```

### 3.6 大小写转换

```java
String s = "Hello World";

s.toLowerCase();        // "hello world"
s.toUpperCase();        // "HELLO WORLD"

// 注意：某些 locale 下的特殊行为
"i".toUpperCase(new Locale("tr"));  // "İ"（土耳其语的点 i 问题！）
// 默认使用默认 locale，需要跨平台一致时指定 Locale.ROOT

```

### 3.7 去除空白

```java
"  Hello  ".trim();          // "Hello"（去除首尾空格，Unicode <= U+0020）

// JDK 11+ 的 strip 系列
"  Hello  ".strip();         // "Hello"（去除首尾所有空白字符）
"  Hello  ".stripLeading();  // "Hello  "
"  Hello  ".stripTrailing(); // "  Hello"

// trim vs strip 的区别：
// trim：只去除 ASCII 空格（<= U+0020）
// strip：去除 Unicode 空白（全角空格等）
"　Hello　".trim();   // "　Hello　"（未去除全角空格）
"　Hello　".strip();  // "Hello"（去除了全角空格）
```

### 3.8 格式字符串

```java
// String.format（底层使用 Formatter）
String.format("Hello %s, you are %d years old", "Alice", 25);
// "Hello Alice, you are 25 years old"

// 常用格式化的类型指示
String.format("%s", "str");     // 字符串
String.format("%d", 42);        // 十进制整数

String.format("%f", 3.14);      // 浮点数：3.140000

```

**Formatter 的性能：**
```java
// String.format 每次都创建 Formatter 对象，大量使用时是性能瓶颈
// 替代方案：
// 1. 简单拼接用 +
// 2. 循环拼接用 StringBuilder

StringBuilder sb = new StringBuilder();

```

## 4. 正则表达式与字符串

### 4.1 Pattern 与 Matcher

```java
// String 的正则方法（内部都使用了 Pattern/Matcher）
// matches()：整体匹配
// replaceAll()、replaceFirst()：替换
// split()：分割

// 推荐：多次使用同一正则时预编译 Pattern
// ❌ 低效：每次调用都编译正则
"Hello123".replaceAll("\\d+", "");  // 每次调用都编译一次

// ✅ 高效：预编译
Pattern DIGIT_PATTERN = Pattern.compile("\\d+");
Matcher matcher = DIGIT_PATTERN.matcher("Hello123");
String result = matcher.replaceAll("");

// 更复杂的匹配操作
Pattern pattern = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher matcher = pattern.matcher("2024-01-01");

if (matcher.matches()) {  // 整体匹配
    System.out.println(matcher.group(0));  // "2024-01-01"
    System.out.println(matcher.group(1));  // "2024"（年）
    System.out.println(matcher.group(2));  // "01"（月）
    System.out.println(matcher.group(3));  // "01"（日）
}

// 查找子序列
Pattern wordPattern = Pattern.compile("\\w+");
Matcher wordMatcher = wordPattern.matcher("Hello World Java");
while (wordMatcher.find()) {
    System.out.println(wordMatcher.group());  // Hello → World → Java
}
```

### 4.2 正则表达式性能陷阱

```java
// 1. 回溯灾难（Catastrophic Backtracking）
// ❌ 极其缓慢（O(2^n)）
Pattern badPattern = Pattern.compile("(a+)+b");
// 输入 "aaaaaaaaac" 会导致大量回溯

// ✅ 优化：避免嵌套量词
Pattern goodPattern = Pattern.compile("a+b");

// 2. 正则表达式超时
// Java 没有内置正则超时机制！
// 可用 Thread.join(timeout) 或 ExecutorService 外部控制

// 3. 预编译最佳实践
//    - 编译为 static final 常量
//    - 设置合理的 flags
Pattern CASE_INSENSITIVE = Pattern.compile("hello", Pattern.CASE_INSENSITIVE);
```

## 5. 字符编码与国际化

### 5.1 Java 的编码体系

```java
// char：UTF-16 编码单元（16 位）
// String：内部使用 UTF-16（JDK 8），或 Latin-1/UTF-16（JDK 9+）

// 编码转换
String s = "你好";

// String → bytes（编码）
byte[] utf8 = s.getBytes(StandardCharsets.UTF_8);     // [你:3字节][好:3字节]
byte[] gbk = s.getBytes("GBK");                        // [你:2字节][好:2字节]
byte[] utf16 = s.getBytes(StandardCharsets.UTF_16BE);  // 每字符2字节+ BOM

// bytes → String（解码）
String fromUtf8 = new String(utf8, StandardCharsets.UTF_8);
String fromGbk = new String(gbk, "GBK");

// ❌ 错误：不要依赖默认编码
new String(bytes);  // 使用平台默认编码（不可移植！）

// ✅ 正确：始终指定编码
new String(bytes, StandardCharsets.UTF_8);
```

### 5.2 Unicode 与代理对

```java
// Unicode 码点（Code Point）范围：U+0000 ~ U+10FFFF
// BMP（基本多语言平面）：U+0000 ~ U+FFFF（一个 char 表示）
// 增补平面：U+10000 ~ U+10FFFF（需要两个 char——代理对）

// Emoji 示例
String emoji = "😀";  // U+1F600

System.out.println(emoji.length());          // 2（两个 char）
System.out.println(emoji.codePointCount(0, emoji.length()));  // 1（一个码点）

// 正确遍历字符串
String text = "Hello😀World🌍";
char[] chars = text.toCharArray();
for (int i = 0; i < chars.length; i++) {
    if (Character.isHighSurrogate(chars[i])) {
        int codePoint = text.codePointAt(i);
        System.out.println(Character.toChars(codePoint));  // 完整的字符
        i++;  // 跳过低位代理
    } else {
        System.out.println(chars[i]);  // BMP 字符
    }
}

// 或使用 codePoints 流
text.codePoints().forEach(cp -> {
    System.out.println(new String(Character.toChars(cp)));
});

// 字符串反转的正确方式
public static String reverse(String str) {
    return new StringBuilder(str).reverse().toString();
    // ❌ 可能破坏代理对！
}

// ✅ 正确处理代理对
public static String reverseCorrect(String str) {
    return str.codePoints()
        .collect(StringBuilder::new,
            StringBuilder::appendCodePoint,
            StringBuilder::append)
        .reverse()
        .toString();
}
```

## 7. 常见面试题

### Q1: `String s = new String("hello")` 创建了几个对象？
```java
// 答案：1 个或 2 个
// 1. 如果常量池中没有 "hello"：
//    - 常量池中创建 "hello" 对象
//    - 堆中创建新的 String 对象（引用常量池的 value）
//    → 共 2 个对象
// 2. 如果常量池中已有 "hello"：
//    - 只在堆中创建新的 String 对象
//    → 共 1 个对象
```

### Q2: String 为什么设计为不可变？
```java
// 1. 常量池共享：多个引用可以安全指向同一个 String 对象
// 2. 哈希缓存：String 的 hashCode 只在首次调用时计算，缓存后无需重新计算
// 3. 安全：类加载、网络连接等场景的参数不会意外被修改
// 4. 线程安全：不可变对象不需要同步
```

### Q3: String、StringBuilder、StringBuffer 的选择？
```java
// - 固定字符串 → String
// - 单线程大量拼接 → StringBuilder
// - 多线程共享可变字符串 → StringBuffer（很少用）
// - 多线程场景更推荐使用线程私有 StringBuider 或 String 拼接
```

### Q4: `==` 比较 String 的陷阱？
```java
String a = "ab";
String b = "a" + "b";        // 常量折叠：编译为 "ab"
System.out.println(a == b);  // true

String c = "a";
String d = c + "b";          // 运行时拼接，创建新对象
System.out.println(a == d);  // false（不同对象）

String e = d.intern();
System.out.println(a == e);  // true（intern 返回常量池引用）
```

### Q5: 如何将字符串反转？
```java
String str = "hello";

// 1. StringBuilder
String reversed = new StringBuilder(str).reverse().toString();  // "olleh"

// 2. 递归
public static String reverse(String s) {
    if (s.isEmpty()) return s;
    return reverse(s.substring(1)) + s.charAt(0);
}

// 3. 字符数组
public static String reverse(String s) {
    char[] chars = s.toCharArray();
    for (int i = 0, j = chars.length - 1; i < j; i++, j--) {
        char tmp = chars[i];
        chars[i] = chars[j];
        chars[j] = tmp;
    }
    return new String(chars);
}

// 注意：以上方法都不处理代理对（surrogate pairs）！
// 包含 Emoji 的字符串反转需要特殊处理
```

### Q6: `" ".isBlank()` vs `" ".isEmpty()` 的区别？
```java
"".isEmpty();         // true（长度为 0）
" ".isEmpty();        // false（长度为 1）
"".isBlank();         // true（JDK 11+）
" ".isBlank();        // true（仅包含空白字符）
"\t\n".isBlank();     // true（制表符和换行符也算空白）

// isBlank 的底层：检查字符串中所有字符是否为 Unicode 空白
// Character.isWhitespace(char)
```

### Q7: 字符串常量池在 JDK 7 中发生了什么变化？
```java
// JDK 6：常量池在方法区（永久代），空间有限
// JDK 7：常量池移到堆中
// JDK 8：永久代被元空间（Metaspace）替代，常量池仍在堆中

// 影响：
// - 移到堆后，常量池大小不再受永久代限制
// - intern() 行为发生变化（JDK 6 复制对象，JDK 7 只存引用）
// - String 大量 intern() 的场景在 JDK 6 容易 OOM: PermGen
```

## 8. 最佳实践

1. **字符串比较使用 `equals()`**：别用 `==`
2. **循环拼接使用 `StringBuilder`**：并提前估算容量
3. **`String.split()` 的 limit 参数**：处理尾随空字符串用负数 limit
4. **预编译正则表达式为 `Pattern` 常量**：避免重复编译
5. **使用 `charAt()` 替代 `startsWith()`**：单字符快很多
6. **始终指定字符编码**：`getBytes("UTF-8")` 而非无参版本
7. **`String.valueOf()` 替代字符串拼接**：基本类型转字符串时
8. **大量字符串去重用 `intern()` 节省内存**：但需注意常量池大小
9. **`StringBuilder` 替代 `StringBuffer`**：单线程下性能更好
10. **使用 `Locale.ROOT` 处理大小写转换**：避免 locale 相关问题
11. **`String.trim()` 改为 `strip()`**：JDK 11+ 支持 Unicode 空白
12. **使用 `codePointCount` 正确统计字符数**：代理对情况下准确
