# Java 枚举与内部类

## 📖 本章导读

### 学习目标
通过本章学习,你将掌握:
- ✅ 枚举的基本语法和高级用法
- ✅ 枚举实现单例模式(最安全)
- ✅ 四种内部类的区别和使用场景
- ✅ 匿名内部类和Lambda的对比
- ✅ EnumSet/EnumMap高性能集合

### 核心概念
**枚举**是特殊的类,继承自java.lang.Enum,提供类型安全的常量。**内部类**可以访问外部类的私有成员,分为成员内部类、静态内部类、局部内部类、匿名内部类。枚举单例是最安全的单例实现方式。

### 知识地图
```
枚举与内部类
├── 枚举(enum)
│   ├── 基本枚举: RED, GREEN, BLUE
│   ├── 带字段方法: Planet(mass, radius)
│   ├── 抽象方法: 每个常量不同实现
│   ├── 实现接口: implements Describable
│   └── 枚举单例: INSTANCE(最安全)
├── 枚举工具类
│   ├── EnumSet: 位向量,极高性能
│   └── EnumMap: 数组实现,key只能是枚举
├── 内部类
│   ├── 成员内部类: 非static,持有外部类引用
│   ├── 静态内部类: static,不持有外部类引用
│   ├── 局部内部类: 方法内定义,JDK 8前需final
│   └── 匿名内部类: 无名字,一次使用
└── 最佳实践
    ├── 状态/类型用枚举替代int常量
    ├── 单例优先用枚举实现
    ├── 避免在循环中创建匿名内部类
    └── 静态内部类优于成员内部类
```

### 常见误区
❌ **误区1**: 枚举可以被继承
✅ **真相**: 枚举隐式final,不能被继承

❌ **误区2**: 成员内部类可以在静态方法中创建
✅ **真相**: 成员内部类需要外部类实例,静态上下文无法创建

❌ **误区3**: 匿名内部类中的this指向自身
✅ **真相**: Lambda的this指向外部类,匿名内部类的this指向自身

### 实战建议
1. **常量定义**: 用枚举替代public static final int
2. **单例模式**: 优先用枚举单例(线程安全+防反射)
3. **状态机**: 用枚举+抽象方法实现不同状态行为
4. **集合优化**: 枚举key用EnumMap,枚举集合用EnumSet
5. **内部类选择**: 不需要外部类引用时用static内部类
6. **内存泄漏**: 长生命周期对象不要持有短生命周期的内部类
7. **Lambda优先**: JDK 8+用Lambda替代匿名内部类

## 1. 枚举（enum）

### 1.1 基本枚举

```java
public enum Color {
    RED, GREEN, BLUE
}

// 使用
Color c = Color.RED;
System.out.println(c);           // "RED"
System.out.println(c.name());    // "RED"
System.out.println(c.ordinal()); // 0
System.out.println(c.compareTo(Color.GREEN));  // -1

// 遍历
for (Color color : Color.values()) {
    System.out.println(color);
}

// 根据名称获取
Color color = Color.valueOf("RED");
```

### 1.2 带字段和方法的枚举

```java
public enum Planet {
    MERCURY(3.302e+23, 2.439e6),
    VENUS(4.869e+24, 6.052e6),
    EARTH(5.975e+24, 6.378e6),
    MARS(6.419e+23, 3.393e6);

    private final double mass;      // 质量
    private final double radius;    // 半径
    private final double surfaceGravity;  // 表面重力

    // 构造器（隐式 private）
    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
        surfaceGravity = 6.67300E-11 * mass / (radius * radius);
    }

    public double mass() { return mass; }
    public double radius() { return radius; }
    public double surfaceGravity() { return surfaceGravity; }

    public double surfaceWeight(double otherMass) {
        return otherMass * surfaceGravity;
    }
}

// 使用
double earthWeight = 75;
double mass = earthWeight / Planet.EARTH.surfaceGravity();
for (Planet p : Planet.values()) {
    System.out.printf("Weight on %s is %f%n", p, p.surfaceWeight(mass));
}
```

### 1.3 枚举中的特定行为

```java
// 不同枚举常量实现不同的行为
public enum Operation {
    PLUS("+") {
        @Override public double apply(double x, double y) { return x + y; }
    },
    MINUS("-") {
        @Override public double apply(double x, double y) { return x - y; }
    },
    TIMES("*") {
        @Override public double apply(double x, double y) { return x * y; }
    },
    DIVIDE("/") {
        @Override public double apply(double x, double y) { return x / y; }
    };

    private final String symbol;

    Operation(String symbol) { this.symbol = symbol; }

    @Override public String toString() { return symbol; }

    // 抽象方法——每个枚举常量必须实现
    public abstract double apply(double x, double y);
}

// 使用
double result = Operation.PLUS.apply(3, 4);  // 7.0
```

### 1.4 枚举实现接口

```java
public interface Describable {
    String getDescription();
}

public enum Status implements Describable {
    PENDING {
        @Override public String getDescription() { return "等待处理"; }
    },
    PROCESSING {
        @Override public String getDescription() { return "处理中"; }
    },
    COMPLETED {
        @Override public String getDescription() { return "已完成"; }
    };
}
```

### 1.5 枚举的源码原理

```java
// 枚举本质上是继承 java.lang.Enum 的 final 类
// 编译器自动生成 values() 和 valueOf() 方法

// 反编译 Color.RED：
// public static final Color RED = new Color("RED", 0);

// 枚举的特性：
// 1. 隐式 final（不能被继承）
// 2. 构造器隐式 private
// 3. 自动继承 java.lang.Enum
// 4. 自动实现 Serializable 和 Comparable
// 5. 不能被克隆（防止单例被破坏）
```

**Enum 的核心方法：**
```java
// name()：枚举常量的名称（字符串）
// ordinal()：枚举常量的顺序（从 0 开始）
// values()：所有枚举常量数组（编译器生成，非 Enum 方法）
// valueOf(String)：根据名称获取枚举常量
// compareTo(E o)：按 ordinal 比较
```

### 1.6 枚举实现单例

```java
// 枚举单例——最简洁、最安全的单例实现
// 自动序列化安全（不会被反射破坏）

public enum Singleton {
    INSTANCE;

    private String data;

    public void setData(String data) {
        this.data = data;
    }

    public String getData() {
        return data;
    }

    public void doSomething() {
        // 业务逻辑
    }
}

// 使用
Singleton.INSTANCE.setData("config");
Singleton.INSTANCE.doSomething();

// 枚举单例的优势：
// 1. 线程安全（JVM 保证枚举创建是线程安全的）
// 2. 抵御反射攻击（Enum 构造器限制）
// 3. 序列化安全（Enum 的序列化有特殊处理）
```

### 1.7 枚举的集合操作

```java
// EnumSet：枚举专用的 Set 实现（位向量，极高性能）
EnumSet<Color> colors = EnumSet.of(Color.RED, Color.BLUE);
EnumSet<Color> all = EnumSet.allOf(Color.class);
EnumSet<Color> none = EnumSet.noneOf(Color.class);
EnumSet<Color> range = EnumSet.range(Color.RED, Color.GREEN);

// 性能：内部使用 long 位向量，单字（64 位）即可覆盖最多 64 个枚举常量
// 比 HashSet 快得多

// EnumMap：枚举专用的 Map 实现（高效数组实现）
EnumMap<Color, String> colorMap = new EnumMap<>(Color.class);
colorMap.put(Color.RED, "#FF0000");
colorMap.put(Color.GREEN, "#00FF00");
```

## 2. 内部类（Inner Class）

### 2.1 内部类概览

```
Java 内部类分为 4 种：

1. 成员内部类（Member Inner Class）
2. 静态内部类（Static Nested Class）
3. 局部内部类（Local Inner Class）
4. 匿名内部类（Anonymous Inner Class）
```

### 2.2 成员内部类

```java
public class Outer {
    private int x = 10;
    private static int staticX = 100;

    // 成员内部类：可以访问外部类的所有成员（包括 private）
    public class Inner {
        private int y = 20;

        public void print() {
            System.out.println(x);            // ✅ 访问外部类实例字段
            System.out.println(staticX);       // ✅ 访问外部类静态字段
            System.out.println(y);             // ✅ 访问自己的字段
        }

        // ❌ 不能有静态成员（JDK 16 之前）
        // public static void staticMethod() { }
    }

    public void createInner() {
        Inner inner = new Inner();  // 外部类中可以直接 new
    }
}

// 使用成员内部类（必须通过外部类实例）
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();

// 或
Outer.Inner inner2 = new Outer().new Inner();
```

**成员内部类的内存结构：**
```java
// 编译器在 Inner 类中生成一个指向外部类实例的引用
// Inner.class 等价于：
// class Outer$Inner {
//     final Outer this$0;  // 隐含的外部类引用
//
//     Inner(Outer outer) {
//         this.this$0 = outer;
//     }
// }

// 这意味着：
// 1. 内部类持有外部类引用 → 外部类不能被 GC
// 2. 内部类构造函数有隐藏参数

// 如果存在内存泄漏风险，考虑使用静态内部类
```

### 2.3 静态内部类

```java
public class Outer {
    private int x = 10;
    private static int staticX = 100;

    // 静态内部类：不持有外部类引用
    public static class StaticInner {
        private int y = 20;
        private static int staticY = 200;  // ✅ 可以有静态成员

        public void print() {
            // System.out.println(x);     // ❌ 不能访问实例字段
            System.out.println(staticX);   // ✅ 可以访问静态字段
        }
    }
}

// 使用（不需要外部类实例）
Outer.StaticInner inner = new Outer.StaticInner();

// 常见用途：构造复杂对象的 Builder
public class Person {
    private String name;
    private int age;

    public static class Builder {
        private String name;
        private int age;

        public Builder setName(String name) { this.name = name; return this; }
        public Builder setAge(int age) { this.age = age; return this; }
        public Person build() { return new Person(name, age); }
    }

    private Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
// Person p = new Person.Builder().setName("Alice").setAge(25).build();
```

### 2.4 局部内部类

```java
public class Outer {
    private int x = 10;

    public void method(int param) {
        final int localVar = 20;  // 必须 effectively final

        // 局部内部类：定义在方法内
        class LocalInner {
            public void print() {
                System.out.println(x);          // ✅ 访问外部类字段
                System.out.println(localVar);   // ✅ 访问局部变量
                System.out.println(param);      // ✅ 访问方法参数
            }
        }

        LocalInner inner = new LocalInner();
        inner.print();
    }
}

// 局部内部类可以访问的变量：
// 1. 外部类的所有成员
// 2. 方法参数和局部变量（必须是 effectively final，JDK 8+）

// 背景：JDK 7 及以前要求局部变量必须是 final
// JDK 8+：effectively final（变量初始化后不再修改）
```

### 2.5 匿名内部类

```java
// 最常用的内部类形式
// 本质是继承父类或实现接口的"一次性"类

// 实现接口
Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running");
    }
};

// 继承类
JButton button = new JButton("Click");
button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        System.out.println("Clicked");
    }
});

// 匿名内部类的限制：
// 1. 不能有显式构造器（但可以使用实例初始化块）
// 2. 不能是抽象类（必须实现所有抽象方法）
// 3. 不能有静态成员

// 实例初始化块替代构造器
new Object() {
    {
        System.out.println("Init block");  // 相当于构造器
    }
};

// JDK 8+ 中匿名内部类通常可以用 Lambda 替代
button.addActionListener(e -> System.out.println("Clicked"));
```

### 2.6 内部类与序列化

```java
// 成员内部类和匿名内部类实现了序列化接口时需谨慎
// 因为它们持有外部类的引用，可能导致外部类的整个对象图被序列化

public class Outer implements Serializable {
    private String data;

    // ❌ 序列化 Inner 会同时序列化 Outer
    public class Inner implements Serializable {
        private String innerData;
    }

    // ✅ 静态内部类不持有外部类引用
    public static class StaticInner implements Serializable {
        private String data;
    }
}

// 如果成员内部类需要序列化，添加 writeReplace 方法
public class Outer {
    public class Inner implements Serializable {
        private Object writeReplace() {
            return new InnerData(Outer.this.data, this.value);
        }
    }
}
```

### 2.7 内部类的编译产物

```java
// 编译后生成的 .class 文件：
// Outer.class
// Outer$Inner.class           ← 成员内部类
// Outer$StaticInner.class     ← 静态内部类
// Outer$1LocalInner.class     ← 局部内部类（数字编号）
// Outer$1.class               ← 匿名内部类（数字编号）
```

## 3. 枚举与内部类的选择

| 场景 | 选择 |
|:---|:---|
| 固定常量集 | 枚举（四季、颜色、状态） |
| 类型安全的枚举 | 枚举（无简单常量的类型安全问题） |
| 单例模式 | 枚举单例 |
| 辅助类与外部类密切相关 | 静态内部类 |
| 需要访问外部类的私有成员 | 成员内部类 |
| 一次性实现 | 匿名内部类 → Lambda |
| Builder 模式 | 静态内部类 Builder |
| 复杂的状态机 | 枚举 + 成员内部类 |

## 4. 面试题

### Q1: 枚举支持继承吗？
```java
// 不支持。枚举隐式继承 java.lang.Enum，Java 不支持多继承
// public enum Color extends Something { }  // ❌ 编译错误
// 但枚举可以实现接口
```

### Q2: 枚举的构造器为什么是 private？
```java
// 枚举常量在类加载时由 JVM 创建，不允许外部创建
// 构造器即使声明为 public 也会被编译器改为 private
// 这是 JVM 规范的强制要求
```

### Q3: 匿名内部类中的 this 指向谁？
```java
// 匿名内部类中的 this 指向匿名内部类的实例
// 要引用外部类实例：Outer.this

Runnable r = new Runnable() {
    @Override
    public void run() {
        // this → Runnable 匿名实现类
        // Outer.this → 外部类实例
    }
};
```

### Q4: 内部类持有外部类引用可能造成什么问题？
```java
// 内存泄漏！
// 如果内部类被长期持有（如静态集合），外部类无法被 GC
// 解决方案：改用静态内部类（不持有外部类引用）
```

### Q5: 枚举可以使用 == 比较吗？
```java
// 可以！枚举常量是单例，== 和 equals() 结果相同
// == 更快，没有 null 安全问题

Color c = Color.RED;
System.out.println(c == Color.RED);     // true（推荐）
System.out.println(c.equals(Color.RED)); // true（也可以）
```

## 5. 最佳实践

1. **需要用固定常量集合时使用枚举**：替代 `public static final int`
2. **枚举用于单例模式**：最安全的单例实现
3. **利用 EnumSet/EnumMap**：比普通集合性能更好
4. **优先静态内部类**：避免非静态内部类的内存泄漏
5. **匿名内部类能用 Lambda 替代时用 Lambda**：代码更简洁
6. **枚举中实现特定行为用抽象方法**：而非 switch
7. **枚举的序数（ordinal）尽量不用**：添加新枚举常量的位置影响序数
8. **内部类编译产物注意安全**：内部类可以访问外部类的 private 成员
