# Java 异常处理机制

## 📖 本章导读

### 学习目标
通过本章学习,你将掌握:
- ✅ Java异常体系结构(Error/Exception/RuntimeException)
- ✅ 受检异常vs非受检异常的选择原则
- ✅ try-catch-finally的正确使用
- ✅ try-with-resources自动资源管理
- ✅ 自定义异常的最佳实践
- ✅ 异常链和异常传播机制

### 核心概念
**异常处理**是Java错误处理的核心机制,通过**受检异常**强制处理可恢复错误,**非受检异常**表示编程错误。**try-with-resources**简化资源管理,**异常链**保留原始错误信息。

### 知识地图
```
异常处理
├── 异常体系
│   ├── Error: JVM级错误(不可恢复)
│   ├── Exception: 程序级异常
│   │   ├── Checked: 编译期检查(IOException等)
│   │   └── Unchecked: RuntimeException(NPE等)
│   └── 设计哲学: 可恢复用Checked,bug用Unchecked
├── 捕获处理
│   ├── try-catch: 基本语法
│   ├── 多异常捕获: catch(A | B e)
│   ├── finally: 始终执行(除System.exit)
│   └── 执行顺序: try→catch→finally→return
├── 资源管理
│   ├── try-with-resources: JDK 7+
│   ├── AutoCloseable接口
│   └── 多个资源自动关闭
├── 抛出异常
│   ├── throw: 手动抛出
│   ├── throws: 方法声明
│   └── 异常链: initCause, getCause
├── 自定义异常
│   ├── 继承Exception: Checked
│   ├── 继承RuntimeException: Unchecked
│   └── 最佳实践: 提供有意义消息
└── 高级特性
    ├── Suppressed Exceptions: 抑制异常
    ├── StackTrace: 堆栈跟踪
    └── 性能考量: 异常创建开销大
```

### 常见误区
❌ **误区1**: catch(Exception e)捕获所有异常
✅ **正确**: 精确捕获具体异常,避免掩盖问题

❌ **误区2**: finally中写return语句
✅ **真相**: finally的return会覆盖try/catch的return,导致意外行为

❌ **误区3**: 吞掉异常(catch后什么都不做)
✅ **正确**: 至少记录日志或重新抛出

### 实战建议
1. **异常选择**: 可恢复用Checked,编程错误用Unchecked
2. **资源管理**: 优先使用try-with-resources
3. **异常链**: 包装异常时保留cause(initCause)
4. **日志记录**: catch块中记录完整堆栈(e.printStackTrace或logger.error)
5. **避免空catch**: 至少记录日志,不要吞掉异常
6. **精确捕获**: 避免catch(Exception),捕获具体类型
7. **自定义异常**: 提供有意义的构造函数和消息

## 1. 异常体系结构

### 1.1 Throwable 层次

```
Object
 └── Throwable (可抛出)
      ├── Error (错误：JVM 级问题，不可恢复)
      │    ├── OutOfMemoryError
      │    ├── StackOverflowError
      │    ├── NoClassDefFoundError
      │    └── ...
      └── Exception (异常：程序级问题，可处理)
           ├── RuntimeException (运行时异常/非受检 Unchecked)
           │    ├── NullPointerException
           │    ├── ArrayIndexOutOfBoundsException
           │    ├── IllegalArgumentException
           │    ├── IllegalStateException
           │    ├── ClassCastException
           │    ├── ArithmeticException
           │    ├── NumberFormatException
           │    └── ...
           └── CheckedException (受检异常)
                ├── IOException
                │    ├── FileNotFoundException
                │    ├── EOFException
                │    └── ...
                ├── SQLException
                ├── ClassNotFoundException
                ├── InterruptedException
                └── ...
```

### 1.2 受检（Checked）vs 非受检（Unchecked）异常

```java
// 受检异常：
// - 继承 Exception 但不继承 RuntimeException
// - 编译器强制处理（catch 或 throws）
// - 代表可预见的、可恢复的错误

// 非受检异常：
// - 继承 RuntimeException
// - 编译器不强制处理（可 catch 也可不 catch）
// - 代表编程错误（bug）或不可恢复的问题

// 受检异常的正确用法（调用者应该能够合理恢复）：
public void readFile(String path) throws FileNotFoundException {
    if (!new File(path).exists()) {
        throw new FileNotFoundException("File not found: " + path);
    }
    // ...
}

// 非受检异常的常见场景（调用者无法恢复）：
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Age cannot be negative: " + age);
    }
    this.age = age;
}
```

**Error 与 Exception 的区别：**
```java
// Error 代表 JVM 级的问题，不应该 catch
try {
    int[] arr = new int[Integer.MAX_VALUE];  // OutOfMemoryError
} catch (OutOfMemoryError e) {
    // ❌ catch Error 通常是不对的，即使 catch 了也无法恢复
}

// 改正：在问题发生前预防
if (someCondition) {
    // 分配可能大量内存前做检查
}
```

### 1.3 回顾：Error 与受检/非受检异常的设计哲学

```
受检异常 → 调用者预期会处理，例如 FileNotFoundException
非受检异常 → 编程错误：空指针、越界等，修复代码而非 catch
Error → JVM 内部错误：OOM、SOF，catch 也于事无补
```

## 2. try-catch-finally

### 2.1 基本语法

```java
try {
    // 可能抛异常的代码
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // 处理特定异常
    System.err.println("算术异常: " + e.getMessage());
} catch (Exception e) {
    // 处理更通用的异常（catch 顺序：子类→父类）
    System.err.println("其他异常: " + e);
} finally {
    // 无论是否抛异常都执行（用于释放资源）
    System.out.println("Always executed");
}
```

### 2.2 多异常捕获（JDK 7+）

```java
try {
    // 可能抛出多种异常
    readFile("test.txt");
} catch (IOException | SQLException e) {
    // 使用 | 合并多个异常（类型必须不存在继承关系）
    // e 默认是 final 的（不可重新赋值）
    System.err.println("IO 或 SQL 异常: " + e);
    // e = new IOException();  // ❌ 编译错误（e 是 final 的）
}
```

### 2.3 finally 的执行细节

```java
// finally 始终执行，除非：
// 1. 线程被终止（Thread.stop/abort）
// 2. JVM 崩溃或退出（System.exit()）

try {
    System.out.println("try");
    System.exit(0);  // JVM 立即退出
} finally {
    System.out.println("finally");  // ❌ 不会执行！
}

// finally 在 return 之后执行！
public int test() {
    try {
        return 1;
    } finally {
        System.out.println("finally");  // 先执行这个
        // 然后才 return 1
    }
}

// ❌ finally 中修改 return 值（反直觉）
public int test2() {
    int x = 1;
    try {
        return x;  // 返回 1
    } finally {
        x = 2;  // 修改 x，但返回的仍是 1（返回值已暂存）
    }
}
// 输出：1（不是 2）

// ❌ 更危险：finally 中的 return 会覆盖 try/catch 中的 return
public int test3() {
    try {
        throw new RuntimeException();
    } catch (RuntimeException e) {
        return 1;  // 被 finally 覆盖
    } finally {
        return 2;  // 最终返回 2！
    }
}

// 原则：不要在 finally 中写 return
```

## 3. try-with-resources（JDK 7+）

### 3.1 自动资源管理

```java
// 要求资源实现 AutoCloseable 或 Closeable 接口

// JDK 7 以前的写法
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("file.txt"));
    return br.readLine();
} catch (IOException e) {
    throw e;
} finally {
    if (br != null) {
        try { br.close(); } catch (IOException e) { /* 忽略 */ }
    }
}

// JDK 7+ 的写法
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"));
     FileWriter fw = new FileWriter("out.txt")) {
    String line = br.readLine();
    fw.write(line);
} // 自动关闭 br 和 fw（按声明逆序）
```

### 3.2 Suppressed 异常

```java
// 当 try 块抛异常且 close() 也抛异常时：
// - 主异常为 try 块中的异常
// - close() 的异常被附加为"被抑制异常"

try (MyResource r = new MyResource()) {
    throw new RuntimeException("try 异常");
} catch (RuntimeException e) {
    System.out.println(e.getMessage());         // "try 异常"
    Throwable[] suppressed = e.getSuppressed();
    System.out.println(suppressed[0].getMessage());  // "close 异常"
}

class MyResource implements AutoCloseable {
    @Override
    public void close() {
        throw new RuntimeException("close 异常");
    }
}
```

## 4. 自定义异常

```java
// 什么时候自定义异常？
// 1. 需要为特定错误提供语义明确的异常类型
// 2. 需要携带额外的错误信息

// 受检异常
public class InsufficientFundsException extends Exception {
    private final double balance;
    private final double amount;

    public InsufficientFundsException(double balance, double amount) {
        super(String.format("余额不足: 需要 %.2f，实际 %.2f", amount, balance));
        this.balance = balance;
        this.amount = amount;
    }

    public double getBalance() { return balance; }
    public double getAmount() { return amount; }
}

// 非受检异常
public class ValidationException extends RuntimeException {
    private final List<String> errors;

    public ValidationException(List<String> errors) {
        super("校验失败: " + String.join(", ", errors));
        this.errors = errors;
    }

    public List<String> getErrors() { return errors; }
}

// 使用自定义异常
public void withdraw(double amount) throws InsufficientFundsException {
    if (amount > this.balance) {
        throw new InsufficientFundsException(this.balance, amount);
    }
    this.balance -= amount;
}
```

**自定义异常最佳实践：**
```java
// 1. 提供多个构造器（模仿标准异常）
public class BusinessException extends RuntimeException {
    public BusinessException() { super(); }
    public BusinessException(String message) { super(message); }
    public BusinessException(String message, Throwable cause) { super(message, cause); }
    public BusinessException(Throwable cause) { super(cause); }
}

// 2. 考虑是否需要区分受检/非受检
// 3. 设计异常时考虑是否需要携带额外数据
// 4. 继承合适的异常基类：
//    - 非法参数 → IllegalArgumentException
//    - 非法状态 → IllegalStateException
//    - IO 错误 → IOException
```

## 5. 异常链（Exception Chaining）

```java
// 异常链：将一个异常包装为另一个异常的一部分

try {
    try {
        // 原始异常
        throw new IOException("磁盘错误");
    } catch (IOException e) {
        // 包装为业务异常并保留原始异常
        throw new BusinessException("业务失败", e);
    }
} catch (BusinessException e) {
    Throwable cause = e.getCause();
    System.out.println(cause.getMessage());  // "磁盘错误"

    // 获取完整异常栈
    e.printStackTrace();
    // BusinessException: 业务失败
    //   at ...
    // Caused by: java.io.IOException: 磁盘错误
    //   at ...
}
```

**异常链的实现机制：**
```java
// Throwable 中通过 cause 字段维护异常链
// public synchronized Throwable initCause(Throwable cause)
// public Throwable getCause()

// 推荐通过构造器传递 cause：
throw new BusinessException("msg", originalException);
// 等价于：
BusinessException e = new BusinessException("msg");
e.initCause(originalException);
throw e;
```

## 7. 异常信息提取

```java
try {
    throw new IllegalArgumentException("参数错误");
} catch (Exception e) {
    // 常用方法
    e.getMessage();          // "参数错误"
    e.getLocalizedMessage(); // 本地化后的信息
    e.toString();            // "java.lang.IllegalArgumentException: 参数错误"
    e.printStackTrace();     // 打印完整堆栈到 stderr
    e.getCause();            // 获取原因异常
    e.getSuppressed();       // 获取被抑制的异常（try-with-resources）

    // 获取堆栈信息为数组
    StackTraceElement[] stack = e.getStackTrace();
    for (StackTraceElement elem : stack) {
        System.out.printf("%s.%s(%s:%d)%n",
            elem.getClassName(),
            elem.getMethodName(),
            elem.getFileName(),
            elem.getLineNumber());
    }
}
```

## 8. finally 与 return 的复杂交互

```java
public class FinallyReturnDemo {

    // 场景 1：finally 修改返回值
    public static int method1() {
        int i = 0;
        try {
            return i;  // 暂存 i=0
        } finally {
            i = 42;     // 修改 i，但返回值还是 0
            System.out.println("finally: i=" + i);
        }
    }

    // 场景 2：finally 中有 return（覆盖 try 的 return）
    public static int method2() {
        try {
            return 1;   // 被 finally 覆盖
        } finally {
            return 2;   // 最终返回 2！
        }
    }

    // 场景 3：finally 中抛异常（覆盖 try 的异常）
    public static void method3() throws Exception {
        try {
            throw new RuntimeException("try 异常");
        } finally {
            throw new Exception("finally 异常");  // 覆盖 try 的异常
        }
    }

    // 场景 4：引用类型的修改
    public static StringBuilder method4() {
        StringBuilder sb = new StringBuilder("hello");
        try {
            return sb;  // 返回 sb 的引用
        } finally {
            sb.append(" world");  // 修改对象！返回值也会受影响
        }
    }
    // method4() 返回 "hello world"
}

public static void main(String[] args) throws Exception {
    System.out.println(method1());        // 0
    System.out.println(method2());        // 2
    try { method3(); } catch (Exception e) {
        System.out.println(e.getMessage());  // "finally 异常"
    }
    System.out.println(method4());        // "hello world"
}
```

## 9. 异常性能开销

```java
// 异常创建的性能开销：
// 1. 填充堆栈信息（fillInStackTrace()）是昂贵的操作
//    - 遍历当前线程的堆栈帧
//    - 为每个帧创建 StackTraceElement 对象
// 2. 异常对象本身的内存开销

// ❌ 不要用异常控制流程
try {
    // 将正常流程异常化
    int index = list.indexOf("item");
    if (index == -1) throw new ItemNotFoundException();
    // ...
} catch (ItemNotFoundException e) {
    // 处理"item 不存在"的流程
}
// ✅ 直接检查返回值
int index = list.indexOf("item");
if (index == -1) {
    // 处理"item 不存在"的流程
} else {
    // 正常流程
}

// ❌ 不要用异常覆盖空值检查
// ❌ 不要循环中捕获异常
```

**异常性能优化：**
```java
// 如果异常经常被抛出且堆栈不需要，可重写 fillInStackTrace
public class LightweightException extends RuntimeException {
    @Override
    public synchronized Throwable fillInStackTrace() {
        // 不填充堆栈（性能提升 10-100 倍）
        return this;
    }

    // 可手动设置消息
    public LightweightException(String message) {
        super(message);
    }
}

// 但是！如果捕获后只是记录日志，不需要堆栈的话
// 更简单的办法是检查前置条件，避免异常发生
```

## 10. 异常处理原则与最佳实践

### 10.1 基本原则

```java
// 1. 异常处理四原则（来自 Effective Java）

// 原则 1：只针对异常情况使用异常
// ❌ 不要用异常控制流程
try {
    int i = 0;
    while (true)
        arr[i++].doSomething();
} catch (ArrayIndexOutOfBoundsException e) { }  // 极端反模式

// 原则 2：使用受检异常恢复，用运行时异常指示编程错误
// 原则 3：避免不必要的受检异常（考虑返回 Optional）
// 原则 4：优先使用标准异常

// 2. 异常粒度
// - 一个 try 块不要捕获太多不同类型的操作
// - catch 要具体（不要总是 catch(Exception)）

// 3. 记录或传播，二选一
// ❌ 既记录又传播
try { ... } catch (IOException e) {
    log.error("错误", e);  // 记录
    throw e;               // 传播（上层又记录一遍，堆栈重复）
}

// ✅ 要么记录，要么传播
try { ... } catch (IOException e) {
    throw new BusinessException("操作失败", e);  // 只传播
}
```

### 10.2 常见的反模式

```java
// ❌ 反模式 1：捕获但什么都不做（吞掉异常）
try {
    riskyOperation();
} catch (Exception e) {
    // 空 catch 块——异常被吞噬，没有任何痕迹
}
// ✅ 如果确实要忽略，记录日志
catch (Exception e) {
    log.warn("操作失败", e);
}

// ❌ 反模式 2：过于宽泛的 catch
try {
    // ...
} catch (Exception e) {  // 捕获所有异常，包括 NullPointerException
    // ...
}
// ✅ 捕获最具体的异常

// ❌ 反模式 3：用异常做条件判断
public String getData(int index) {
    try {
        return list.get(index);  // 抛出 IndexOutOfBoundsException
    } catch (IndexOutOfBoundsException e) {
        return null;  // 等价于 index 检查
    }
}
// ✅ 应该用条件判断：
if (index < list.size()) {
    return list.get(index);
}
return null;
```

### 10.3 日志记录规范

```java
// 日志等级与异常结合：
// - ERROR：不可恢复错误（系统/功能不可用）
// - WARN：可恢复的错误（重试成功、降级）
// - INFO：预期内的异常处理
// - DEBUG：调试用详细信息

// 记录异常的两个关键：
// 1. 记录异常消息和堆栈
log.error("处理失败", exception);     // ✅ 包含完整堆栈
log.error("处理失败: " + e.getMessage());  // ❌ 丢失堆栈

// 2. 记录上下文信息
log.error("处理用户 {} 的订单 {} 失败", userId, orderId, exception);
```

## 11. 面试题

### Q1: final、finally、finalize 的区别？
```java
// final：关键字，修饰类（不可继承）、方法（不可重写）、变量（不可变）
// finally：异常处理块，始终执行
// finalize：Object 方法，GC 前调用（JDK 9+ 已废弃）
```

### Q2: 如果 try 中有 return，finally 中还有 return，会怎样？
```java
// finally 中的 return 会覆盖 try 中的 return
// 编译会报警告，但不报错
// 永远不要在 finally 中写 return
```

### Q3: 受检异常能否在 RuntimeException 的子类方法中抛出？
```java
// 可以！如果方法声明了 throws，其 override 版本可以抛更少的异常
// 但不能抛父类未声明的受检异常

class Parent {
    void method() throws IOException { }
}
class Child extends Parent {
    // ✅ 不抛异常
    void method() { }
    // ✅ 抛运行时异常（RuntimeException 不受限制）
    void method() throws RuntimeException { }
    // ❌ 抛父类未声明的受检异常
    // void method() throws SQLException { }
}
```

### Q4: NoClassDefFoundError 和 ClassNotFoundException 的区别？
```java
// ClassNotFoundException：受检异常，动态加载类时找不到
//   → Class.forName()、ClassLoader.loadClass()
// NoClassDefFoundError：Error，编译时存在但运行时找不到
//   → 类路径问题、依赖缺失
```

### Q5: try-with-resources 中多个异常的优先级？
```java
// try 块中的异常优先于 close() 的异常
// close() 的异常被附加到 try 异常的 suppressed 列表
// 如果 try 正常完成，close() 的异常正常抛出
```

---

## 12. 最佳实践总结

1. **异常用于异常情况**：不要用异常控制流程
2. **使用标准异常**：IllegalArgumentException、IllegalStateException 等
3. **捕获最具体的异常**：不要总 catch(Exception)
4. **不要吞掉异常**：要么记录、要么传播、要么恢复
5. **不要捕获 Throwable/Error**：OOM、StackOverflow 等无法恢复
6. **finally 不要写 return**：会覆盖 try/catch 的返回值
7. **try-with-resources 管理资源**：自动关闭，代码简洁
8. **异常粒度适中**：一个 try 块捕获逻辑相关的操作
9. **异常链提供上下文**：包装异常时保留原始异常（cause）
10. **记录异常包含堆栈**：log.error(msg, e) 而非 log.error(msg + e)
