### 核心概念
**反射(Reflection)**是Java语言的核心特性之一,允许程序在运行时动态地获取类的信息并操作对象。**注解(Annotation)**是一种元数据机制,可以标注代码元素并携带额外信息。两者结合构成了现代Java框架(Spring、MyBatis等)的基石。

### 常见误区
❌ **误区1**: 反射和匿名内部类一样会生成.class文件
✅ **真相**: Lambda使用invokedynamic指令,不会生成额外的类文件,性能更好

❌ **误区2**: 反射可以破坏任何单例模式
✅ **真相**: 枚举单例无法被反射破坏,因为JVM会抛出IllegalArgumentException

❌ **误区3**: 注解只能在运行时使用
✅ **真相**: 注解有SOURCE、CLASS、RUNTIME三种生命周期,只有RUNTIME才能在运行时读取

❌ **误区4**: setAccessible(true)在任何情况下都有效
✅ **真相**: JDK 9+的模块系统可以限制反射,非开放模块的私有成员无法访问

### 实战建议
1. **反射尽量缓存**: Class、Method、Field对象缓存后重用,避免重复查找
2. **优先使用注解而非标记接口**: 更灵活,可携带元数据,如Spring的@Component
3. **业务代码避免反射**: 反射仅用于框架代码,业务代码应直接使用API
4. **注解明确Retention**: 默认CLASS,运行时读取需显式设为RUNTIME
5. **枚举单例最安全**: 防止反射攻击,保证真正的单例
6. **@Override总是使用**: 编译器检查,防止拼写错误导致不是重写
7. **MethodHandle替代场景**: 性能要求高的动态调用场景

## 1. 反射（Reflection）

### 1.1 Class 对象

```java
// 获取 Class 对象的三种方式

// 1. 类名.class
Class<String> clazz1 = String.class;

// 2. 对象.getClass()
String s = "hello";
Class<? extends String> clazz2 = s.getClass();

// 3. Class.forName()
Class<?> clazz3 = Class.forName("java.lang.String");

// 三者得到的 Class 对象相同（同一个类的 Class 对象唯一）
System.out.println(clazz1 == clazz2);  // true
System.out.println(clazz1 == clazz3);  // true

// Class 对象提供的信息
System.out.println(clazz1.getName());       // "java.lang.String"
System.out.println(clazz1.getSimpleName()); // "String"
System.out.println(clazz1.getPackage());    // "java.lang"
System.out.println(clazz1.getSuperclass()); // "java.lang.Object"
System.out.println(clazz1.getModifiers());  // public final
```

### 1.2 获取类信息

```java
Class<?> clazz = String.class;

// 类信息
clazz.getName();                    // 全限定名
clazz.getSimpleName();              // 简单名
clazz.getPackage();                 // 包
clazz.getModifiers();               // 修饰符
clazz.getSuperclass();              // 父类
clazz.getInterfaces();              // 实现的接口
clazz.getClassLoader();             // 类加载器

// 字段（成员变量）
Field[] fields = clazz.getFields();          // 本类 + 父类的 public 字段
Field[] declared = clazz.getDeclaredFields(); // 本类所有字段（不含继承）

// 方法
Method[] methods = clazz.getMethods();            // public 方法（含继承）
Method[] declaredM = clazz.getDeclaredMethods();  // 本类所有方法

// 构造器
Constructor<?>[] constructors = clazz.getConstructors();

// 注解
Annotation[] annotations = clazz.getAnnotations();
```

### 1.3 操作字段

```java
public class User {
    private String name = "default";
    public int age;
}

// 读取和修改字段
Class<User> clazz = User.class;
User user = new User();

// 读取 public 字段
Field ageField = clazz.getField("age");
System.out.println(ageField.get(user));  // 0

// 读取 private 字段（需要 setAccessible）
Field nameField = clazz.getDeclaredField("name");
nameField.setAccessible(true);  // 突破 private 限制
System.out.println(nameField.get(user));  // "default"

// 修改 private 字段
nameField.set(user, "Alice");
System.out.println(user.getName());  // "Alice"

// 获取字段类型和泛型
Type genericType = nameField.getGenericType();
// TypeVariable? ParameterizedType? Class?
```

### 1.4 操作方法

```java
Class<User> clazz = User.class;
User user = new User();

// 调用 public 方法
Method setName = clazz.getMethod("setName", String.class);
setName.invoke(user, "Bob");

// 调用 private 方法
Method privateMethod = clazz.getDeclaredMethod("privateMethod");
privateMethod.setAccessible(true);
privateMethod.invoke(user);

// 调用静态方法
Method staticMethod = clazz.getMethod("staticMethod");
staticMethod.invoke(null);  // 静态方法第一个参数传 null

// 获取返回类型
Method method = clazz.getMethod("getName");
Class<?> returnType = method.getReturnType();

// 获取参数类型
Class<?>[] paramTypes = method.getParameterTypes();
```

### 1.5 操作构造器

```java
Class<User> clazz = User.class;

// 调用无参构造器
User user1 = clazz.getConstructor().newInstance();

// 调用有参构造器
Constructor<User> constructor = clazz.getConstructor(String.class, int.class);
User user2 = constructor.newInstance("Alice", 25);

// 调用 private 构造器（破坏单例模式）
Constructor<User> privateCon = clazz.getDeclaredConstructor(String.class);
privateCon.setAccessible(true);
User user3 = privateCon.newInstance("Bob");

// 注意：通过反射可以绕过私有构造器，但枚举不行
// Constructor<EnumSingleton> con = EnumSingleton.class.getDeclaredConstructor();
// con.newInstance();  // ❌ IllegalArgumentException: Cannot reflectively create enum objects
```

### 1.6 操作数组

```java
// 使用 java.lang.reflect.Array 操作数组

// 创建数组
int[] arr = (int[]) Array.newInstance(int.class, 10);

// 读写元素
Array.set(arr, 0, 42);
int value = Array.getInt(arr, 0);

// 多维数组
int[][] matrix = (int[][]) Array.newInstance(int.class, 3, 4);

// 获取数组的 Class
Class<?> arrayClass = int[].class;
System.out.println(arrayClass.isArray());            // true
System.out.println(arrayClass.getComponentType());  // int
```

### 1.7 反射的性能问题

```java
// 反射比直接调用慢 1-3 个数量级

// 性能开销来源：
// 1. Class.forName 的类查找
// 2. 方法查找（遍历方法表）
// 3. 安全检查（setAccessible 后可关闭）
// 4. 自动装箱/拆箱
// 5. 方法调用时的额外处理

// 优化：
// 1. 缓存 Method/Field/Constructor 对象（避免重复查找）
// 2. setAccessible(true) 关闭安全检查
// 3. 使用 invoke 前确保类型匹配（减少装箱）

// JDK 7+ 的 MethodHandle 比反射更快
// JDK 7+ 的 invokedynamic 使得 Lambda 没有反射开销
```

### 1.8 MethodHandle（JDK 7+）

```java
import java.lang.invoke.*;

public class MethodHandleDemo {
    public void hello(String name) {
        System.out.println("Hello, " + name);
    }

    public static void main(String[] args) throws Throwable {
        MethodHandles.Lookup lookup = MethodHandles.lookup();
        MethodType mt = MethodType.methodType(void.class, String.class);

        MethodHandle mh = lookup.findVirtual(MethodHandleDemo.class, "hello", mt);
        // MethodHandle 类似于反射的 Method，但更快

        MethodHandleDemo demo = new MethodHandleDemo();
        mh.invoke(demo, "Alice");  // "Hello, Alice"
        // 或
        mh.bindTo(demo).invoke("Bob");  // "Hello, Bob"
    }
}

// MethodHandle 与反射的区别：
// - 反射是 Java 语言层面的模拟，MethodHandle 是 JVM 层面的
// - MethodHandle 可以配合 invokedynamic 指令实现动态语言特性
// - MethodHandle 有类型检查，类型不匹配会抛 WrongMethodTypeException
```

## 2. 注解（Annotation）

### 2.1 注解的定义

```java
// @interface 声明注解

public @interface Override { }        // 最简单的标记注解

// 带成员的注解
public @interface RequestMapping {
    String value() default "";        // 注解成员——看起来像方法
    RequestMethod method() default RequestMethod.GET;
    String[] headers() default {};
}

// 注解成员的类型限制：
// - 基本类型（int, String, Class, enum, Annotation, 以及它们的数组）
// - 不能是包装类（Integer 不行）
// - 不能用 null 作为默认值
```

### 2.2 元注解

```java
// 元注解：用于修饰其他注解的注解

// @Retention：注解的生命周期
@Retention(RetentionPolicy.SOURCE)    // 仅在源码中，编译时丢弃
@Retention(RetentionPolicy.CLASS)     // 保留在 class 文件中（默认）
@Retention(RetentionPolicy.RUNTIME)   // 运行时可通过反射获取

// @Target：注解的适用目标
@Target(ElementType.TYPE)               // 类、接口、枚举
@Target(ElementType.FIELD)              // 字段
@Target(ElementType.METHOD)             // 方法
@Target(ElementType.PARAMETER)          // 参数
@Target(ElementType.CONSTRUCTOR)        // 构造器
@Target(ElementType.LOCAL_VARIABLE)     // 局部变量
@Target(ElementType.ANNOTATION_TYPE)    // 注解
@Target(ElementType.PACKAGE)            // 包
@Target(ElementType.TYPE_PARAMETER)     // 类型参数（JDK 8）
@Target(ElementType.TYPE_USE)           // 类型使用（JDK 8）

// @Inherited：子类继承注解
@Inherited
@Retention(RetentionPolicy.RUNTIME)
public @interface InheritableAnnotation { }

// @Documented：包含在 Javadoc 中
@Documented
public @interface DocumentedAnnotation { }

// @Repeatable：允许在同一位置重复使用（JDK 8）
@Repeatable(Schedules.class)
public @interface Schedule {
    String dayOfMonth() default "first";
}

public @interface Schedules {
    Schedule[] value();
}

// 使用
@Schedule(dayOfMonth = "last")
@Schedule(dayOfMonth = "first")
public void doRepeatedTask() { }
```

### 2.3 注解的读取（反射）

```java
// 运行时读取注解（Retention 必须是 RUNTIME）

// 获取类上的注解
@RequestMapping mapping = MyController.class.getAnnotation(RequestMapping.class);
RequestMapping[] all = MyController.class.getAnnotationsByType(RequestMapping.class);

// 判断是否有注解
if (MyController.class.isAnnotationPresent(RequestMapping.class)) { }

// 获取方法上的注解
for (Method method : MyController.class.getMethods()) {
    if (method.isAnnotationPresent(RequestMapping.class)) {
        RequestMapping mapping = method.getAnnotation(RequestMapping.class);
        System.out.println(mapping.value());
    }
}

// 获取字段上的注解
for (Field field : User.class.getDeclaredFields()) {
    if (field.isAnnotationPresent(Inject.class)) { }
}

// 获取参数上的注解（JDK 8）
Method method = MyController.class.getMethod("handle", String.class);
Annotation[][] paramAnnotations = method.getParameterAnnotations();

// 获取包上的注解
Package pkg = MyController.class.getPackage();
Annotation[] pkgAnnotations = pkg.getAnnotations();
```

### 2.4 运行时注解处理器示例

```java
// 定义注解
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface ValidLength {
    int min() default 0;
    int max() default Integer.MAX_VALUE;
    String message() default "字段长度超出范围";
}

// 使用注解
public class User {
    @ValidLength(min = 2, max = 20, message = "用户名长度需在 2-20 之间")
    private String name;

    @ValidLength(min = 6, max = 30)
    private String password;
}

// 注解处理器
public class Validator {
    public static void validate(Object obj) throws Exception {
        Class<?> clazz = obj.getClass();
        for (Field field : clazz.getDeclaredFields()) {
            ValidLength annotation = field.getAnnotation(ValidLength.class);
            if (annotation != null) {
                field.setAccessible(true);
                String value = (String) field.get(obj);
                if (value == null || value.length() < annotation.min()
                    || value.length() > annotation.max()) {
                    throw new IllegalArgumentException(
                        field.getName() + ": " + annotation.message());
                }
            }
        }
    }
}

// 使用
User user = new User();
user.setName("A");  // 太短
Validator.validate(user);  // ❌ 抛异常
```

```java

}
```

## 3. 面试题

### Q1: 反射的用途？实际应用场景？
```java
// 1. Spring/MyBatis 的依赖注入（@Autowired 通过反射赋值）
// 2. ORM 框架（通过反射读取实体类字段，生成 SQL）
// 3. JSON 序列化/反序列化（Jackson/Gson 通过反射读写字段）
// 4. JUnit 测试框架（@Test 注解的方法被反射调用）
// 5. IDE 自动补全（通过反射分析类的所有成员）
// 6. 动态代理（JDK Proxy 通过反射生成代理类）
```

### Q2: @Retention 的三种策略的区别？
```java
// SOURCE：源码级，编译后丢弃
//   → @Override、@SuppressWarnings
// CLASS：保留到 class 文件，运行时不可获取（默认）
//   → 编译工具使用，但不需要运行时
// RUNTIME：运行时可通过反射获取
//   → Spring 的 @Component、JUnit 的 @Test
```

### Q3: 反射破坏单例模式？如何防御？
```java
// 反射可以通过 setAccessible(true) 调用私有构造器

// 防御方式 1：构造器中检测
public class Singleton {
    private static boolean flag = false;

    private Singleton() {
        synchronized (Singleton.class) {
            if (flag) throw new RuntimeException("单例已被破坏");
            flag = true;
        }
    }
}

// 防御方式 2：使用枚举（最可靠）
// 枚举的构造器反射会抛 IllegalArgumentException
```

### Q4: setAccessible(true) 是否安全？
```java
// Java 9+ 的模块系统可以限制反射
// 在 module-info.java 中：
// exports com.example.core;
// opens com.example.core to spring.core;

// 非开放模块的私有成员无法通过反射访问（即使 setAccessible(true)）
```

## 4. 最佳实践

1. **反射尽量缓存**：Class、Method、Field 对象缓存后重用
2. **关闭安全检查**：获取 Method/Field 后立即 `setAccessible(true)`
3. **优先使用注解而非标记接口**：更灵活，可携带元数据
4. **注解定义要明确 Retention**：默认 CLASS，运行时读取需设为 RUNTIME
5. **枚举单例防范反射**：反射对枚举构造器无效
6. **@FunctionalInterface 标注函数式接口**：编译器检查
7. **@Override 总是使用**：防止拼写错误导致不是重写
8. **反射仅用于框架代码**：业务代码尽量避免反射
9. **JDK 9+ 模块化限制反射**：跨模块反射需在 module-info 中 open
10. **MethodHandle 替代反射场景**：性能更好，JVM 级别支持
