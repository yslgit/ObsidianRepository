### 核心概念
**函数式编程**是一种以函数为基本单位的编程范式，强调不变性和无副作用。**响应式编程**是函数式编程在异步数据流领域的延伸，核心是数据流和变化传播。Java 8 的 Lambda + Stream 开启了函数式编程的大门，而 **Project Reactor** 和 **RxJava** 是响应式编程在 JVM 上的主要实现。

### 常见误区
❌ **误区 1**：Stream 一定比 for 循环快
✅ **真相**：Stream 封装了迭代、优化和并行化，但在小数据量时，for 循环由于没有抽象开销，实际更快。Stream 的优势在可读性和大数据量（特别是并行流）时体现。

❌ **误区 2**：响应式编程就是异步编程
✅ **真相**：响应式编程包含异步，但核心是数据流和声明式处理。异步只是实现方式，本质是"对数据流的变化做出反应"。

❌ **误区 3**：WebFlux 比 MVC 快
✅ **真相**：WebFlux 的主要优势不是快，而是在同样资源下支持更多并发连接。单个请求的响应时间两者相近，但 WebFlux 用更少的线程处理更多的并发。

❌ **误区 4**：Optional 就是避免 NPE
✅ **真相**：Optional 的主要意义是"声明可能为空"，让调用者明确知道需要处理空值。但不适合所有场景（如字段类型、方法参数、集合中的元素）。

### 实战建议
1. **Stream 优先于 for**：代码更简洁，但注意不要过度嵌套
2. **并行流慎用**：仅适用于数据量大且操作无状态、可拆分的场景
3. **Optional 用于返回值**：不要用作字段类型或方法参数
4. **WebFlux 适用 IO 密集型**：计算密集型用 MVC + 线程池
5. **背压必须实现**：响应式编程不实现背压就不是真正的响应式

## 1. 函数式编程基础

### 1.1 纯函数与引用透明

```java
// 纯函数（Pure Function）：
// 1. 相同的输入永远得到相同的输出
// 2. 没有副作用（不修改外部状态）

// ✅ 纯函数
public int add(int a, int b) {
    return a + b;
}

// ❌ 非纯函数（依赖外部状态）
private int multiplier = 2;
public int multiply(int a) {
    return a * multiplier;  // 结果取决于 multiplier 的值
}

// ❌ 非纯函数（有副作用）
public int incrementAndGet() {
    return counter++;  // 修改了外部状态
}

// 引用透明（Referential Transparency）：
// 表达式可以用它的计算结果替换而不改变程序行为
int result = add(1, add(2, 3));
// 等价于：
int result = add(1, 5);  // add(2, 3) 替换为 5
// 等价于：
int result = 6;          // add(1, 5) 替换为 6
```

### 1.2 不变性

```java
// 不可变对象（Immutability）是函数式编程的核心

// ✅ 不可变类
public final class Person {
    private final String name;
    private final int age;
    private final List<String> tags;  // 注意：需要防御性拷贝

    public Person(String name, int age, List<String> tags) {
        this.name = name;
        this.age = age;
        // 防御性拷贝——防止外部修改
        this.tags = tags == null ? List.of() : List.copyOf(tags);
    }

    public String getName() { return name; }
    public int getAge() { return age; }
    public List<String> getTags() { return tags; }  // List.copyOf 返回不可变视图

    // 修改时返回新对象（with 风格）
    public Person withAge(int newAge) {
        return new Person(this.name, newAge, this.tags);
    }
}

// Java 9+ 不可变集合：
List.of("a", "b")         // 不可变 List
Set.of(1, 2, 3)           // 不可变 Set
Map.of("k1", "v1")        // 不可变 Map
List.copyOf(list)         // 拷贝为不可变 List
```

### 1.3 高阶函数

```java
// 高阶函数（Higher-Order Function）：
// 1. 接收函数作为参数
// 2. 返回函数作为结果

// 接收函数作为参数
public static <T> List<T> filter(List<T> list, Predicate<T> predicate) {
    List<T> result = new ArrayList<>();
    for (T item : list) {
        if (predicate.test(item)) {
            result.add(item);
        }
    }
    return result;
}

// 返回函数作为结果
public static Function<Integer, Integer> multiplier(int factor) {
    return x -> x * factor;  // 闭包：捕获 factor 变量
}

// 使用
Function<Integer, Integer> doubler = multiplier(2);
Function<Integer, Integer> tripler = multiplier(3);
System.out.println(doubler.apply(5));  // 10
System.out.println(tripler.apply(5));  // 15

// 函数组合
Function<Integer, Integer> f = x -> x + 1;
Function<Integer, Integer> g = x -> x * 2;

Function<Integer, Integer> fThenG = f.andThen(g);  // g(f(x))
Function<Integer, Integer> gThenF = f.compose(g);  // f(g(x))

System.out.println(fThenG.apply(3));  // (3+1)*2 = 8
System.out.println(gThenF.apply(3));  // (3*2)+1 = 7
```

### 1.4 柯里化

```java
// 柯里化（Currying）：将多参数函数转换为单参数函数链

// 传统多参数
Function<Integer, Function<Integer, Function<Integer, Integer>>> add3 =
    a -> b -> c -> a + b + c;

// 使用
int result = add3.apply(1).apply(2).apply(3);  // 6

// 柯里化的好处：部分应用（Partial Application）
Function<Integer, Function<Integer, Integer>> add5 = add3.apply(5);
Function<Integer, Integer> add5and3 = add5.apply(3);
System.out.println(add5and3.apply(2));  // 5 + 3 + 2 = 10

// 实际应用——日志级别部分应用
public class Logger {
    private final String prefix;

    public Logger(String prefix) { this.prefix = prefix; }

    // 柯里化日志方法
    public Function<String, Consumer<String>> log(Level level) {
        return format -> msg ->
            System.out.printf("[%s] [%s] %s: %s%n",
                Thread.currentThread().getName(), level, format, msg);
    }
}
```

## 2. Java 函数式接口

### 2.1 四大核心函数式接口

```java
// ┌──────────────┬───────────────┬────────────────────────────┐
// │ 接口          │ 方法签名       │ 用途                        │
// ├──────────────┼───────────────┼────────────────────────────┤
// │ Consumer<T>   │ void accept(T)│ 消费一个参数                 │
// │ Supplier<T>   │ T get()       │ 提供一个值                   │
// │ Function<T,R> │ R apply(T)    │ 转换一个值                   │
// │ Predicate<T>  │ boolean test(T)│ 判断一个条件                 │
// └──────────────┴───────────────┴────────────────────────────┘

// Consumer：消费
Consumer<String> printer = s -> System.out.println(s);
Consumer<String> logger = s -> System.out.println("[LOG] " + s);
printer.andThen(logger).accept("Hello");  // 链式调用

// Supplier：供应
Supplier<Double> random = () -> Math.random();
Supplier<UUID> uuid = UUID::randomUUID;
// 惰性求值
public <T> T getOrCompute(Supplier<T> supplier) {
    return supplier.get();
}

// Function：转换
Function<String, Integer> toLength = String::length;
Function<String, String> toUpper = String::toUpperCase;
Function<String, String> transform = toUpper.andThen(s -> s + "!");

// Predicate：判断
Predicate<String> isNotEmpty = s -> s != null && !s.isEmpty();
Predicate<String> isLong = s -> s.length() > 10;
Predicate<String> isValid = isNotEmpty.and(isLong);
Predicate<String> isInvalid = isValid.negate();
```

### 2.2 基本类型特化

```java
// 避免装箱/拆箱的性能损失

// 基本类型 Function：
IntFunction<String> intToString = String::valueOf;
ToIntFunction<String> stringToInt = Integer::parseInt;
IntUnaryOperator square = x -> x * x;

// 使用基本类型版本提升性能（避免装箱）
List<Integer> numbers = Arrays.asList(1, 2, 3, 4, 5);
int sum = numbers.stream()
    .mapToInt(Integer::intValue)     // IntStream（基本类型流）
    .sum();

// 基本类型 Consumer：
IntConsumer printInt = System.out::println;

// 基本类型 Supplier：
IntSupplier randomInt = () -> (int) (Math.random() * 100);

// 双参数版本：
BiFunction<String, Integer, User> createUser = User::new;
BiPredicate<String, String> equalsIgnoreCase = String::equalsIgnoreCase;
BiConsumer<String, Integer> printPair = (s, i) -> System.out.println(s + ": " + i);
```

### 2.3 方法引用

```java
// 方法引用（Method Reference）是 Lambda 的简洁写法

// 静态方法引用： Class::staticMethod
Function<String, Integer> parser = Integer::parseInt;    // (s) -> Integer.parseInt(s)
Comparator<Integer> cmp = Integer::compare;               // (a, b) -> Integer.compare(a, b)

// 实例方法引用（特定对象）： instance::method
String str = "hello";
Supplier<Integer> len = str::length;                       // () -> str.length()

// 实例方法引用（任意对象）： Class::instanceMethod
Function<String, Integer> len2 = String::length;           // (s) -> s.length()
Predicate<String> empty = String::isEmpty;                 // (s) -> s.isEmpty()
BiPredicate<String, String> eq = String::equals;           // (a, b) -> a.equals(b)

// 构造器引用： Class::new
Supplier<List<String>> listFactory = ArrayList::new;       // () -> new ArrayList<>()
Function<String, User> userFactory = User::new;            // (name) -> new User(name)

// 数组构造器：
IntFunction<int[]> arrayFactory = int[]::new;              // (n) -> new int[n]
```

## 3. Lambda 原理

### 3.1 invokedynamic 指令

```java
// Lambda 表达式的编译结果：

// 源代码：
// Runnable r = () -> System.out.println("Hello");

// 编译后（字节码层面）：
// invokedynamic #run, bootstrap = LambdaMetafactory.metafactory()
// 等价于生成了一个 lambda$0 方法：
// private static void lambda$0() {
//     System.out.println("Hello");
// }

// LambdaMetafactory.metafactory() 的 3 个关键参数：
// 1. samMethodType：函数式接口的方法签名（void run()）
// 2. implMethod：实际实现的方法句柄（lambda$0）
// 3. instantiatedMethodType：运行时签名

// invokedynamic 的优势：
// 1. 延迟生成：第一次调用时才生成实现类
// 2. 轻量：不生成 .class 文件
// 3. JIT 友好：可以内联
// 4. 免去匿名内部类的类加载开销
```

### 3.2 变量捕获

```java
// Lambda 可以捕获外部变量，但要求"effectively final"

// effectively final：变量初始化后不再改变
public void test() {
    int localVar = 42;           // effectively final
    String str = "hello";        // effectively final

    // Lambda 中可以捕获
    Runnable r = () -> System.out.println(localVar + str);

    // 如果修改编译错误
    int x = 1;
    // x++;  // 编译错误：被 lambda 捕获的变量必须是 effectively final
    // Runnable r2 = () -> System.out.println(x);
}

// 对象引用型可以修改对象内部状态，但不能修改引用本身
public void testObject() {
    StringBuilder sb = new StringBuilder("hello");
    sb.append(" world");  // ✅ 对象内部状态可以修改
    // sb = new StringBuilder();  // ❌ 不能修改引用
    Runnable r = () -> System.out.println(sb);
}

// 数组"绕过"限制（不推荐）
public void testArray() {
    int[] holder = new int[]{0};
    Runnable r = () -> {
        holder[0]++;  // 可以修改数组元素
    };
    // 因为 holder 引用本身没有变，只是数组内容变了
}
```

### 3.3 Lambda vs 匿名内部类

```java
// 1. this 指向不同
// 匿名内部类：this 指向匿名类实例
// Lambda：this 指向外部类实例

public class LambdaThisDemo {
    private String value = "outer";

    public void test() {
        // 匿名内部类
        Runnable r1 = new Runnable() {
            private String value = "inner";
            @Override
            public void run() {
                System.out.println(this.value);  // "inner"
            }
        };

        // Lambda
        Runnable r2 = () -> {
            System.out.println(this.value);  // "outer" (Lambda 的 this 等同于外部类 this)
        };
    }
}

// 2. 编译产物
// 匿名内部类：生成单独的 .class 文件（Outer$1.class）
// Lambda：invokedynamic 动态生成，无单独 .class

// 3. 性能
// 匿名内部类：类加载 + 对象创建开销
// Lambda：invokedynamic 更轻量，JIT 更友好

// 4. 序列化
// 匿名内部类：不能序列化（除非实现 Serializable）
// Lambda：也不能序列化
```

## 4. Stream API

### 4.1 惰性求值

```java
// Stream 有两个阶段：
// 1. 中间操作（Intermediate）：惰性求值，不触发计算
// 2. 终端操作（Terminal）：及早求值，触发计算

// 中间操作：
// filter、map、flatMap、peek、distinct、sorted、limit、skip

// 终端操作：
// forEach、collect、reduce、count、anyMatch、allMatch、noneMatch、findFirst、findAny

// 示例——验证惰性求值
Stream<String> stream = Stream.of("a", "b", "c")
    .filter(s -> {
        System.out.println("filter: " + s);
        return s.length() > 0;
    })
    .map(s -> {
        System.out.println("map: " + s);
        return s.toUpperCase();
    });
// 此时 filter 和 map 都没有执行！没有终端操作！

// 添加终端操作才会触发
List<String> result = stream.collect(Collectors.toList());
// 输出：
// filter: a
// map: a
// filter: b
// map: b
// filter: c
// map: c

// Stream 是垂直执行（逐个元素经过所有操作），不是水平执行（先全部 filter 再全部 map）
// 这称为"循环融合"（Loop Fusion）——减少遍历次数
```

### 4.2 常用操作

```java
// 1. map：转换（1 对 1）
List<String> names = users.stream()
    .map(User::getName)
    .collect(Collectors.toList());

// 2. filter：过滤（1 对 0 或 1）
List<User> adults = users.stream()
    .filter(u -> u.getAge() >= 18)
    .collect(Collectors.toList());

// 3. flatMap：展平（1 对 N）
List<String> allTags = users.stream()
    .map(User::getTags)           // Stream<List<String>>
    .flatMap(List::stream)        // Stream<String>
    .distinct()
    .collect(Collectors.toList());

// 4. reduce：归约
int sum = numbers.stream().reduce(0, Integer::sum);
Optional<Integer> sumOpt = numbers.stream().reduce(Integer::sum);

// 5. collect：收集
List<String> list = stream.collect(Collectors.toList());
Set<String> set = stream.collect(Collectors.toSet());
String joined = stream.collect(Collectors.joining(", "));
Map<Integer, List<User>> byAge = users.stream()
    .collect(Collectors.groupingBy(User::getAge));
Map<Boolean, List<User>> partitioned = users.stream()
    .collect(Collectors.partitioningBy(u -> u.getAge() >= 18));

// 6. findFirst / findAny
Optional<User> first = users.stream()
    .filter(u -> u.getAge() > 18)
    .findFirst();
// findFirst：并行流中保持相遇顺序
// findAny：并行流中性能更好（不保证顺序）

// 7. anyMatch / allMatch / noneMatch
boolean anyAdult = users.stream().anyMatch(u -> u.getAge() >= 18);
boolean allAdult = users.stream().allMatch(u -> u.getAge() >= 18);
boolean noneChild = users.stream().noneMatch(u -> u.getAge() < 18);
// 这三个是短路操作（短路的中间操作：limit、skip）
```

### 4.3 Collector 自定义

```java
// 自定义 Collector

// 例子：收集为 ImmutableList
public class ImmutableListCollector<T>
        implements Collector<T, List<T>, List<T>> {

    @Override
    public Supplier<List<T>> supplier() {
        return ArrayList::new;           // 可变容器
    }

    @Override
    public BiConsumer<List<T>, T> accumulator() {
        return List::add;                // 如何添加元素
    }

    @Override
    public BinaryOperator<List<T>> combiner() {
        return (left, right) -> {        // 合并两个容器（并行流）
            left.addAll(right);
            return left;
        };
    }

    @Override
    public Function<List<T>, List<T>> finisher() {
        return Collections::unmodifiableList;  // 最终转换
    }

    @Override
    public Set<Characteristics> characteristics() {
        return EnumSet.of(Characteristics.CONCURRENT);
        // CONCURRENT：支持并发
        // IDENTITY_FINISH：finisher 是恒等函数（可省略）
        // UNORDERED：不保持顺序
    }
}

// 使用：
List<String> immutable = stream.collect(new ImmutableListCollector<>());

// 更简单的方式——使用 collectingAndThen：
List<String> immutable2 = stream.collect(
    Collectors.collectingAndThen(
        Collectors.toList(),
        Collections::unmodifiableList
    )
);
```

### 4.4 并行流

```java
// 并行流（parallel stream）使用 ForkJoinPool.commonPool()

// 适合并行流的条件：
// 1. 数据量大（> 10000 个元素）
// 2. 操作无状态，可拆分
// 3. 计算密集而非 IO 密集

// 示例：
int sum = numbers.parallelStream()
    .filter(n -> n > 0)
    .mapToInt(Integer::intValue)
    .sum();

// 并行流的陷阱：

// 陷阱 1：共享可变状态（线程不安全）
// ❌
List<Integer> result = new ArrayList<>();
numbers.parallelStream()
    .filter(n -> n > 0)
    .forEach(result::add);  // ArrayList 线程不安全！
// ✅
List<Integer> result = numbers.parallelStream()
    .filter(n -> n > 0)
    .collect(Collectors.toList());

// 陷阱 2：阻塞操作
// ❌ 会阻塞公共池中的所有线程
numbers.parallelStream()
    .forEach(n -> {
        String data = httpClient.get("/data/" + n);  // 阻塞调用
        process(data);
    });

// 陷阱 3：reduce 必须满足结合律
// ❌
int sum = numbers.parallelStream()
    .reduce(0, (a, b) -> a - b);  // 减法不满足结合律！
// 并行时结果不定
```

### 4.5 Stream 性能

```java
// Stream 与 for 循环的性能对比

// JDK 8 之前：
// for 循环 ≈ Stream（小数据量）
// for 循环 > Stream（大数据量基本类型）

// JDK 8+（JIT 优化后）：
// for 循环 ≈ Stream（基本类型）
// for 循环 > Stream（引用类型，因为装箱）
// parallelStream > for 循环（大数据量，计算密集）

// 建议：
// - 集合操作：优先用 Stream（可读性好）
// - 基本类型数组操作：for 循环（IntStream 也可以）
// - 大数据量耗时操作：parallelStream
// - 小数据量：for 循环或 Stream 都行

// 多阶段操作的 Stream 优化：
// 循环融合（Loop Fusion）——多个中间操作合并为一次遍历
// Stream.of(1, 2, 3)
//     .filter(x -> x > 1)       // 和下面的 map 融合为一次遍历
//     .map(x -> x * 2)
```

## 5. Optional

### 5.1 创建与使用

```java
// Optional 的创建：
Optional<String> empty = Optional.empty();                    // 空
Optional<String> nonNull = Optional.of("hello");              // 非空（null 抛 NPE）
Optional<String> nullable = Optional.ofNullable(someString);  // 可以为 null

// 基本操作：
Optional<String> opt = Optional.of("hello");

// 判读
opt.isPresent()   // true
opt.isEmpty()     // false（JDK 11+）

// 获取值（不推荐直接 get）
opt.get()                       // "hello"（为空时抛 NoSuchElementException）
opt.orElse("default")           // "hello"（orElse 始终计算默认值）
opt.orElseGet(() -> compute())  // "hello"（惰性计算默认值）
opt.orElseThrow(() -> new RuntimeException("not found"))

// 转换
opt.map(String::length)              // Optional<Integer>
opt.filter(s -> s.length() > 3)      // Optional<String>
opt.flatMap(s -> Optional.of(s.length()))  // Optional<Integer>

// 消费
opt.ifPresent(s -> System.out.println(s));
opt.ifPresentOrElse(
    s -> System.out.println(s),
    () -> System.out.println("empty")
);  // JDK 9+

// JDK 9+ 新增：
opt.or(() -> Optional.of("fallback"))  // Optional<String>
opt.stream()                           // Stream<String>
```

### 5.2 Optional 链式编程

```java
// Optional 的链式调用避免深层 if-null 检查

// ❌ 多层 null 检查
public String getCity(User user) {
    if (user != null) {
        Address address = user.getAddress();
        if (address != null) {
            City city = address.getCity();
            if (city != null) {
                return city.getName();
            }
        }
    }
    return "unknown";
}

// ✅ Optional 链式
public String getCity(User user) {
    return Optional.ofNullable(user)
        .map(User::getAddress)          // Optional<Address>
        .map(Address::getCity)          // Optional<City>
        .map(City::getName)             // Optional<String>
        .orElse("unknown");
}

// 配合 Stream 使用
public List<String> getCities(List<User> users) {
    return users.stream()
        .map(User::getAddress)
        .filter(Objects::nonNull)
        .map(Address::getCity)
        .filter(Objects::nonNull)
        .map(City::getName)
        .collect(Collectors.toList());
}
```

### 5.3 Optional 反模式

```java
// ❌ 反模式 1：Optional 作为字段类型
public class User {
    private Optional<String> name;  // 不推荐！
}
// 理由：Optional 不可序列化，增加了复杂度
// 正确：用 @Nullable 注解或默认值

// ❌ 反模式 2：Optional 作为方法参数
public void setName(Optional<String> name) {  // 不推荐！
    this.name = name.orElse("default");
}
// 理由：调用方仍需检查 null，没有意义
// 正确：使用方法重载
public void setName(String name) { this.name = name; }
public void setName() { this.name = "default"; }

// ❌ 反模式 3：Optional 作为集合中的元素
List<Optional<String>> list = new ArrayList<>();  // 不推荐！
// 正确：过滤 null
List<String> cleanList = list.stream()
    .filter(Objects::nonNull)
    .collect(Collectors.toList());

// ❌ 反模式 4：用 Optional 做判断
if (opt.isPresent()) {  // 不如直接用 if (value != null)
    doSomething(opt.get());
}
// ✅ 正确：
opt.ifPresent(this::doSomething);
```

## 6. 响应式编程

### 6.1 Reactive Streams 规范

```java
// Reactive Streams 是 JVM 响应式编程的标准（JDK 9 纳入 java.util.concurrent.Flow）

// 4 个核心接口：

// 1. Publisher：数据发布者
@FunctionalInterface
public interface Publisher<T> {
    void subscribe(Subscriber<? super T> subscriber);
}

// 2. Subscriber：数据订阅者
public interface Subscriber<T> {
    void onSubscribe(Subscription subscription);  // 订阅成功
    void onNext(T item);                           // 接收到数据
    void onError(Throwable throwable);             // 出错
    void onComplete();                             // 完成
}

// 3. Subscription：订阅令牌（控制背压）
public interface Subscription {
    void request(long n);   // 请求 n 个元素（背压）
    void cancel();           // 取消订阅
}

// 4. Processor：既是 Publisher 又是 Subscriber
public interface Processor<T, R> extends Subscriber<T>, Publisher<R> {
}

// JDK 9 Flow API（java.util.concurrent.Flow）：
// Flow.Publisher
// Flow.Subscriber
// Flow.Subscription
// Flow.Processor

// 规范的背压流程：
// 1. Subscriber.subscribe(publisher) → publisher.onSubscribe(subscription)
// 2. Subscriber 通过 subscription.request(N) 告诉发布者一次最多发 N 个
// 3. Publisher 逐条调用 subscriber.onNext(item)
// 4. 当 Subscriber 想继续接收时，再次调用 subscription.request(N)
// 5. 完成时调用 onComplete()，出错时调用 onError()
```

### 6.2 Project Reactor

```java
// Reactor 是 Spring WebFlux 的底层依赖
// 两个核心类型：Flux（0~N 个元素）和 Mono（0~1 个元素）

// 创建 Flux：
Flux<String> flux1 = Flux.just("a", "b", "c");
Flux<Integer> flux2 = Flux.range(1, 10);
Flux<Long> flux3 = Flux.interval(Duration.ofSeconds(1));  // 无限流
Flux<String> flux4 = Flux.fromStream(Stream.of("x", "y"));

// 创建 Mono：
Mono<String> mono1 = Mono.just("hello");
Mono<String> mono2 = Mono.empty();
Mono<String> mono3 = Mono.justOrEmpty(optional);
Mono<String> mono4 = Mono.fromCallable(() -> {
    // 惰性执行
    return "result";
});

// 操作符（与 Stream 非常相似）：
Flux<String> flux = Flux.just("a", "bb", "ccc")
    .filter(s -> s.length() > 1)
    .map(String::toUpperCase)
    .flatMap(s -> Flux.just(s.split("")));  // 展平

// 订阅：
flux.subscribe(
    data -> System.out.println("Data: " + data),  // onNext
    err -> System.err.println("Error: " + err),    // onError
    () -> System.out.println("Done")               // onComplete
);

// 背压控制：
flux.subscribe(new BaseSubscriber<String>() {
    @Override
    protected void hookOnSubscribe(Subscription subscription) {
        request(1);  // 一次只请求 1 个
    }

    @Override
    protected void hookOnNext(String value) {
        process(value);
        request(1);  // 处理完再请求下一个
    }
});
```

### 6.3 Reactor 操作符

```java
// 1. 创建操作符
Mono<String> mono = Mono.fromSupplier(() -> compute());
Flux<String> flux = Flux.defer(() -> Flux.fromStream(loadStream()));  // 惰性

// 2. 转换操作符
flux.map(s -> s.length());                        // 同步转换
flux.flatMap(s -> asyncCall(s));                  // 异步转换（返回 Publisher）
flux.concatMap(s -> asyncCall(s));                // 有序 flatMap

// 3. 过滤操作符
flux.filter(s -> s.length() > 3);
flux.distinct();
flux.take(5);                                     // 取前 5 个
flux.skip(2);                                     // 跳过前 2 个

// 4. 组合操作符
Flux<String> combined = Flux.concat(flux1, flux2);       // 先后拼接
Flux<String> merged = Flux.merge(flux1, flux2);          // 交叉合并（按到达时间）
Flux<Tuple2<String, Integer>> zipped = Flux.zip(flux1, flux2);  // 一对一压缩

// 5. 错误处理（核心）
flux.onErrorReturn("fallback")                    // 返回默认值
    .onErrorResume(e -> fallbackFlux(e))          // 切换到备选流
    .onErrorMap(e -> new BusinessException(e))    // 转换异常类型
    .retry(3)                                      // 重试 3 次
    .retryBackoff(3, Duration.ofSeconds(1));       // 指数退避重试

// 6. 超时
mono.timeout(Duration.ofSeconds(5))
    .onErrorReturn("timeout");

// 7. 调度器（Schedulers）
flux.subscribeOn(Schedulers.parallel())   // 订阅在哪个线程池执行
    .publishOn(Schedulers.boundedElastic());  // 后续操作在哪个线程池执行

// 调度器类型：
Schedulers.immediate();          // 当前线程
Schedulers.single();             // 单线程
Schedulers.parallel();           // 固定线程池（CPU 密集）
Schedulers.boundedElastic();     // 弹性线程池（IO 密集，推荐）
Schedulers.fromExecutorService(executor);  // 自定义
```

### 6.4 WebFlux

```java
// Spring WebFlux 是响应式 Web 框架

// MVC vs WebFlux：
// ┌──────────────┬──────────────────────┬──────────────────────┐
// │              │ Spring MVC           │ Spring WebFlux       │
// ├──────────────┼──────────────────────┼──────────────────────┤
// │ 模型         │ 同步（每个请求一个线程）│ 异步（事件驱动）      │
// │ IO 类型      │ 阻塞 IO              │ 非阻塞 IO            │
// │ 数据库访问   │ JDBC（阻塞）          │ R2DBC（非阻塞）      │
// │ 性能         │ 吞吐量受线程限制      │ 高并发下吞吐量更高    │
// │ 学习成本     │ 低                  │ 高                   │
// │ 适用场景     │ 计算密集/传统应用     │ IO 密集/高并发        │
// └──────────────┴──────────────────────┴──────────────────────┘

// WebFlux Controller（注解方式）：
@RestController
@RequestMapping("/users")
public class UserController {

    @Autowired
    private UserRepository userRepository;

    @GetMapping("/{id}")
    public Mono<User> getUser(@PathVariable String id) {
        return userRepository.findById(id);
    }

    @GetMapping
    public Flux<User> getAllUsers() {
        return userRepository.findAll();
    }

    @PostMapping
    public Mono<User> createUser(@RequestBody User user) {
        return userRepository.save(user);
    }
}

// WebFlux Router（函数式方式，替代注解）：
@Configuration
public class RouterConfig {
    @Bean
    public RouterFunction<ServerResponse> route(UserHandler handler) {
        return RouterFunctions.route()
            .GET("/users/{id}", handler::getUser)
            .GET("/users", handler::getAllUsers)
            .POST("/users", handler::createUser)
            .build();
    }
}

@Component
public class UserHandler {
    public Mono<ServerResponse> getUser(ServerRequest request) {
        String id = request.pathVariable("id");
        return userRepository.findById(id)
            .flatMap(user -> ServerResponse.ok().bodyValue(user))
            .switchIfEmpty(ServerResponse.notFound().build());
    }

    public Mono<ServerResponse> getAllUsers(ServerRequest request) {
        return ServerResponse.ok()
            .body(userRepository.findAll(), User.class);
    }
}

// WebClient（响应式 HTTP 客户端，替代 RestTemplate）：
@Service
public class UserService {
    // 非阻塞式 HTTP 请求
    private final WebClient webClient = WebClient.create("http://api.example.com");

    public Mono<User> getUser(String id) {
        return webClient.get()
            .uri("/users/{id}", id)
            .retrieve()
            .bodyToMono(User.class)
            .timeout(Duration.ofSeconds(5))
            .onErrorResume(e -> Mono.empty());
    }
}
```

### 6.5 背压实战

```java
// 背压（Backpressure）：消费者告诉生产者"慢点，我处理不过来"

// 场景：从数据库读取大量数据，写入文件
// 不使用背压——可能 OOM：
Flux<User> users = userRepository.findAll();
users.subscribe(user -> {
    // 如果处理速度慢于数据库查询速度
    // 数据会在内存中堆积 → OOM
});

// 使用背压——控制流速：
public class BackpressureDemo {
    public static void main(String[] args) {
        // 创建一个每秒发射 1000 个元素的 Flux
        Flux.interval(Duration.ofMillis(1))
            .map(i -> "Item " + i)
            .log()
            .subscribe(new BaseSubscriber<String>() {
                @Override
                protected void hookOnSubscribe(Subscription subscription) {
                    request(5);  // 一开始只请求 5 个
                }

                @Override
                protected void hookOnNext(String value) {
                    process(value);
                    // 每处理完一个，请求下一个
                    // 实际上这样相当于"逐个处理"
                    request(1);
                }

                private void process(String value) {
                    // 模拟慢处理
                    try {
                        Thread.sleep(100);
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                    System.out.println("Processed: " + value);
                }
            });

        // 阻塞主线程
        Thread.sleep(10000);
    }
}

// 操作符层面的背压：
flux.onBackpressureBuffer(1000)     // 缓冲最多 1000 个（默认策略）
    .onBackpressureDrop()           // 丢弃溢出的元素
    .onBackpressureLatest()         // 只保留最新的
    .subscribe(subscriber);
```

## 7. 面试题

### Q1：Stream 的中间操作和终端操作有什么区别？

```java
// 中间操作（Intermediate）：
// - 返回 Stream（可以链式调用）
// - 惰性求值（不会触发计算）
// - 如：filter、map、flatMap、distinct、sorted、peek、limit、skip

// 终端操作（Terminal）：
// - 返回结果或副作用
// - 触发计算（开始遍历数据）
// - 如：forEach、collect、reduce、count、anyMatch、allMatch、findFirst

// 区别记忆法：中间操作描述"做什么"，终端操作"真正去做"
```

### Q2：Lambda 和匿名内部类的区别？

```java
// 1. this 指向不同
// 匿名内部类 this → 匿名类实例
// Lambda this → 外部类实例

// 2. 编译策略不同
// 匿名内部类 → 生成单独的 .class 文件
// Lambda → invokedynamic 指令，运行时动态生成

// 3. 性能不同
// Lambda 更轻量，不需要加载额外的类文件
// JIT 对 invokedynamic 的内联更友好

// 4. 变量捕获要求相同
// 都需要 effectively final
```

### Q3：flatMap 和 map 的区别？

```java
// map：1 对 1 转换
// 输入 Stream<T>，输出 Stream<R>
// 每个元素转换为另一个元素

// flatMap：1 对 N 转换 + 展平
// 输入 Stream<T>，输出 Stream<R>（合并所有子流）
// 每个元素转换为一个流，然后展平所有流

// 类比：
// map:   [[1,2],[3,4]] → [[2,4],[6,8]]  （每个元素*2）
// flatMap: [[1,2],[3,4]] → [1,2,3,4]      （展平）
```

### Q4：什么是背压？为什么需要背压？

```java
// 背压（Backpressure）是响应式编程中的流量控制机制
// 消费者告诉生产者自己的处理能力，避免生产者发送过快

// 没有背压的问题：
// 生产者 1000/秒 → 消费者 100/秒 → 数据堆积 → OOM

// 背压的解决方案：
// 1. BUFFER：缓冲（默认，可能导致 OOM）
// 2. DROP：丢弃（丢失数据）
// 3. LATEST：只保留最新
// 4. ERROR：报错
// 5. 自定义：request(N) 控制流速

// 背压是响应式编程区别于"异步编程"的关键
```

### Q5：Mono 和 Flux 的区别？

```java
// Mono：0 或 1 个元素的异步序列
// 类似 Optional + 异步
// 适用：单个结果查询、单个对象操作

// Flux：0 到 N 个元素的异步序列
// 类似 Stream + 异步
// 适用：列表查询、数据流处理

// 转换关系：
// Mono<List<T>> → Flux<T>（.flatMapMany(Flux::fromIterable)）
// Flux<T> → Mono<List<T>>（.collectList()）
// Flux<T> → Mono<Long>（.count()）

// 注意：Mono 和 Flux 都是冷的——没有人订阅就不会执行
```

### Q6：响应式编程和普通异步编程的区别？

```java
// 普通异步编程（CompletableFuture）：
// - 一次执行，返回一个结果
// - 没有时间维度的概念
// - 没有背压
// - 处理的是单个值

// 响应式编程（Reactor）：
// - 处理数据流（随时间推移产生的一系列数据）
// - 有数据流的生命周期（onSubscribe → onNext* → onComplete/onError）
// - 有背压机制
// - 丰富的操作符（组合、转换、过滤、错误处理）

// 类比：
// CompletableFuture = 一个快递包裹（一次性的）
// Reactive Streams = 一条传送带上的数据流（持续的）
```
