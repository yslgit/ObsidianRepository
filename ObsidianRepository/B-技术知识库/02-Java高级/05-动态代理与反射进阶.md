### 核心概念
**动态代理**是指在运行时动态创建代理类对象，而不是在编译期确定的。JDK 动态代理基于接口（通过 Proxy + InvocationHandler），CGLIB 基于继承（通过字节码生成子类）。**反射进阶**涵盖 MethodHandle（JVM 级别的动态调用）、VarHandle（字段原子操作）、以及 invokedynamic 指令（Lambda 底层实现）。

### 常见误区
❌ **误区 1**：JDK 动态代理只能代理接口方法
✅ **真相**：JDK 动态代理要求目标类必须实现接口，代理类只能调用接口中声明的方法。但目标类可以有其他方法，只是无法通过代理访问。

❌ **误区 2**：CGLIB 可以代理任何类
✅ **真相**：CGLIB 不能代理 final 类，也不能代理 final 方法和 static 方法（因为通过生成子类的方式实现代理）。

❌ **误区 3**：JDK 动态代理比 CGLIB 慢
✅ **真相**：JDK 8+ 之后，JDK 动态代理的调用性能已经优于 CGLIB。但 CGLIB 的代理类创建速度更快（不需要编译）。

❌ **误区 4**：反射调用就是 Method.invoke()
✅ **真相**：JDK 7+ 引入了 MethodHandle，它是比反射更底层的 JVM 级别动态调用机制，配合 invokedynamic 可以实现更高效的动态调用。

### 实战建议
1. **Spring 场景**：目标类有接口时默认 JDK 代理，需 CGLIB 时配置 `proxy-target-class=true`
2. **MyBatis Mapper**：使用 JDK 动态代理生成 Mapper 接口的实现
3. **高性能场景**：JDK 8+ 首选 JDK 动态代理，CGLIB 仅当目标类没有接口时使用
4. **MethodHandle 场景**：性能敏感的动态调用（如序列化框架、脚本引擎）
5. **字节码框架选型**：简单生成用 Javassist，高级操作用 ASM/ByteBuddy

## 1. JDK 动态代理

### 1.1 基本用法

```java
// 接口
public interface UserService {
    void addUser(String name);
    String getUser(int id);
}

// 目标类
public class UserServiceImpl implements UserService {
    @Override
    public void addUser(String name) {
        System.out.println("Adding user: " + name);
    }

    @Override
    public String getUser(int id) {
        return "User-" + id;
    }
}

// InvocationHandler（横切逻辑）
public class LogHandler implements InvocationHandler {
    private final Object target;

    public LogHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[LOG] Before method: " + method.getName());
        long start = System.nanoTime();

        Object result = method.invoke(target, args);  // 调用目标方法

        long elapsed = System.nanoTime() - start;
        System.out.println("[LOG] After method: " + method.getName()
            + " (" + elapsed / 1000 + "μs)");

        return result;
    }
}

// 使用
UserService target = new UserServiceImpl();
UserService proxy = (UserService) Proxy.newProxyInstance(
    target.getClass().getClassLoader(),       // 类加载器
    target.getClass().getInterfaces(),         // 要实现的接口
    new LogHandler(target)                     // InvocationHandler
);

proxy.addUser("Alice");   // 调用代理方法
String user = proxy.getUser(1);
```

### 1.2 运行时生成的代理类

```java
// Proxy.newProxyInstance 在运行时动态生成代理类的字节码
// 生成的代理类结构如下（反编译）：

// package com.sun.proxy;
//
// public final class $Proxy0 extends Proxy implements UserService {
//     private static Method m1;  // equals
//     private static Method m3;  // addUser
//     private static Method m4;  // getUser
//     private static Method m2;  // toString
//     private static Method m0;  // hashCode
//
//     public $Proxy0(InvocationHandler h) {
//         super(h);  // 存为 this.h
//     }
//
//     public final void addUser(String name) {
//         try {
//             // 所有方法调用都转发给 InvocationHandler
//             super.h.invoke(this, m3, new Object[]{name});
//             return;
//         } catch (RuntimeException | Error e) {
//             throw e;
//         } catch (Throwable e) {
//             throw new UndeclaredThrowableException(e);
//         }
//     }
//
//     public final String getUser(int id) {
//         try {
//             return (String) super.h.invoke(this, m4, new Object[]{id});
//         } catch (RuntimeException | Error e) {
//             throw e;
//         } catch (Throwable e) {
//             throw new UndeclaredThrowableException(e);
//         }
//     }
// }

// 生成的代理类特点：
// 1. 继承 java.lang.reflect.Proxy
// 2. 实现指定的所有接口
// 3. 所有方法 final（不可被子类重写）
// 4. 所有方法调用委托给 InvocationHandler.invoke()
// 5. 类名格式：$Proxy0, $Proxy1, $Proxy2 ...
```

### 1.3 Proxy.newProxyInstance 源码

```java
// Proxy.newProxyInstance 源码分析：
public static Object newProxyInstance(ClassLoader loader,
                                      Class<?>[] interfaces,
                                      InvocationHandler h) {
    Objects.requireNonNull(h);

    final Class<?>[] intfs = interfaces.clone();

    // 1. 查找或生成代理类
    Class<?> cl = getProxyClass0(loader, intfs);

    // 2. 获取构造器（参数为 InvocationHandler）
    final Constructor<?> cons = cl.getConstructor(constructorParams);

    // 3. 通过构造器创建代理实例
    return cons.newInstance(new Object[]{h});
}

// getProxyClass0 的核心逻辑（缓存 + 生成）：
private static Class<?> getProxyClass0(ClassLoader loader,
                                       Class<?>... interfaces) {
    // 接口数量上限（65535）
    if (interfaces.length > 65535) {
        throw new IllegalArgumentException("interface limit exceeded");
    }

    // 从缓存中获取（WeakCache）
    return proxyClassCache.get(loader, interfaces);
}

// 缓存未命中时，通过 ProxyGenerator 生成代理类字节码
// ProxyGenerator.generateProxyClass() 生成字节码

// 可以查看生成的代理类字节码：
byte[] classBytes = ProxyGenerator.generateProxyClass(
    "$Proxy0", new Class[]{UserService.class});
try (FileOutputStream fos = new FileOutputStream("$Proxy0.class")) {
    fos.write(classBytes);
}
```

### 1.4 JDK 动态代理的限制

```java
// 限制 1：必须基于接口
// 以下用法会抛出 IllegalArgumentException：
// Proxy.newProxyInstance(loader, new Class[]{MyClass.class}, handler);
// 如果 MyClass 不是接口而是类 → ❌ IllegalArgumentException

// 限制 2：只能代理接口中声明的方法
public class MyClass {
    public void publicMethod() { }
    public void extraMethod() { }
}

interface MyInterface {
    void publicMethod();
}

// 通过 MyInterface 代理，只能调用 publicMethod()
// extraMethod() 无法通过代理访问

// 限制 3：方法转发必须有 InvocationHandler
// 如果 handler 为 null → NullPointerException
// handler.invoke() 中不调用 method.invoke(target) 则目标方法不会执行

// 限制 4：生成的代理类继承 Proxy，不能继承其他类
// $Proxy0 extends Proxy implements UserService
// 不像 CGLIB 可以继承目标类

// 限制 5（JDK 9+）：模块化限制
// 如果目标类所在的包没有对调用者模块开放
// setAccessible 会抛 InaccessibleObjectException
```

### 1.5 JDK 动态代理的优化

```java
// 性能优化建议：

// 1. 缓存 Method 对象（Proxy 已经做了）
// 代理类中的 Method m1, m2, m3 等是 static final 的
// 不需要额外缓存

// 2. 避免装箱
// 如果接口方法接收基本类型参数，invoke 中会装箱
// 在 InvocationHandler 中注意类型转换

// 3. 减少反射调用
// 如果 InvocationHandler 中的逻辑简单，性能影响不大
// 不要在 invoke 中做复杂的反射操作

// 4. 使用 lambda 实现 InvocationHandler
// JDK 8+，注意 lambda 变量捕获
UserService proxy = (UserService) Proxy.newProxyInstance(
    loader, interfaces,
    (proxy1, method, args) -> {
        System.out.println("Before " + method.getName());
        Object result = method.invoke(target, args);
        System.out.println("After " + method.getName());
        return result;
    }
);
```

## 2. CGLIB 动态代理

### 2.1 基本用法

```java
// CGLIB（Code Generation Library）基于 ASM 的字节码增强库
// 通过生成目标类的子类来实现代理

// 导入依赖（CGLIB 是 Spring 的默认依赖，不需要额外引入）
// <dependency>
//     <groupId>cglib</groupId>
//     <artifactId>cglib</artifactId>
//     <version>3.3.0</version>
// </dependency>

// 目标类（不需要接口）
public class UserService {
    public void addUser(String name) {
        System.out.println("Adding user: " + name);
    }

    public final String getFinal() {   // final 方法不能被代理
        return "final";
    }

    public static void staticMethod() {  // static 方法不能被代理
        System.out.println("static");
    }
}

// MethodInterceptor（CGLIB 的 InvocationHandler 等价物）
public class LogInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args,
                            MethodProxy proxy) throws Throwable {
        System.out.println("[LOG] Before: " + method.getName());
        long start = System.nanoTime();

        // 注意：这里调用 proxy.invokeSuper 而不是 method.invoke
        Object result = proxy.invokeSuper(obj, args);

        long elapsed = System.nanoTime() - start;
        System.out.println("[LOG] After: " + method.getName()
            + " (" + elapsed / 1000 + "μs)");

        return result;
    }
}

// 创建代理
public class CglibDemo {
    public static void main(String[] args) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(UserService.class);      // 设置父类
        enhancer.setCallback(new LogInterceptor());      // 设置拦截器
        // 可选：设置拦截器过滤
        enhancer.setCallbackFilter(method -> {
            if ("addUser".equals(method.getName())) {
                return 0;  // 使用 LogInterceptor
            }
            return 1;      // 使用 NoOp.INSTANCE（不代理）
        });
        // enhancer.setCallbacks(new Callback[]{new LogInterceptor(), NoOp.INSTANCE});

        UserService proxy = (UserService) enhancer.create(); // 创建代理
        proxy.addUser("Alice");
        proxy.getFinal();  // ❌ 不会被代理（final 方法）
    }
}
```

### 2.2 CGLIB 生成的代理类

```java
// CGLIB 运行时生成的代理类（反编译效果）：
// 继承目标类 + 实现 Factory 接口

// public class UserService$$EnhancerByCGLIB$$xxx extends UserService
//         implements Factory {
//
//     private MethodInterceptor CGLIB$CALLBACK_0;  // 拦截器
//     private static Method CGLIB$addUser$0$Method;
//     private static MethodProxy CGLIB$addUser$0$Proxy;
//
//     static {
//         CGLIB$addUser$0$Method = ReflectUtils.findMethod(
//             "com.example.UserService", "addUser", ...);
//         CGLIB$addUser$0$Proxy = MethodProxy.create(
//             "UserService", "UserService$$EnhancerByCGLIB$$xxx",
//             "addUser", "(Ljava/lang/String;)V");
//     }
//
//     // 覆盖目标类的方法
//     public final void addUser(String name) {
//         // 如果没有设置拦截器 → 直接调用父类
//         if (CGLIB$CALLBACK_0 != null) {
//             // 调用拦截器
//             CGLIB$CALLBACK_0.intercept(this,
//                 CGLIB$addUser$0$Method,
//                 new Object[]{name},
//                 CGLIB$addUser$0$Proxy);
//         } else {
//             super.addUser(name);
//         }
//     }
// }

// CGLIB 代理类特点：
// 1. 继承目标类（所以 final 类无法代理）
// 2. 覆盖所有非 final、非 static 方法
// 3. 使用 MethodProxy 加速调用（比反射快）
// 4. 生成多个回调方法（fastClass）
```

### 2.3 MethodProxy 与 FastClass

```java
// CGLIB 的核心优化：FastClass 机制

// 传统反射调用：
// method.invoke(target, args)
// → 每次调用都需做安全检查、参数类型检查等

// MethodProxy.invokeSuper()：
// 使用 FastClass 直接调用父类方法
// FastClass 在编译时确定方法索引，运行时不需反射

// FastClass 原理：
// CGLIB 为每个类生成两个 FastClass：
// 1. 目标类的 FastClass（包含索引数组）
// 2. 代理类的 FastClass

// 生成的 FastClass 类似：
public class UserService$$FastClassByCGLIB$$xxx extends FastClass {
    // 方法索引
    private static final int ADD_USER = 0;
    private static final int GET_USER = 1;
    // ...

    public Object invoke(int index, Object obj, Class[] paramTypes, Object[] args) {
        UserService target = (UserService) obj;
        switch (index) {
            case 0:
                target.addUser((String) args[0]);
                return null;
            case 1:
                return target.getUser((Integer) args[0]);
            // ...
        }
    }
}

// 通过索引调用，避免了反射的 Method.invoke() 开销
// 这是 CGLIB 比 JDK 动态代理快的原因之一（JDK 8 之前）

// JDK 8+ 优化的反射调用：
// JDK 8 修改了 Method.invoke() 的实现
// 加入 inflate 机制（委派模式），高频调用时生成 Native 代码
// 使 JDK 动态代理性能追上甚至超过 CGLIB
```

### 2.4 JDK 动态代理 vs CGLIB 对比


## 3. 字节码操作框架

### 3.1 ASM

```java
// ASM 是最底层的字节码操作框架
// 直接操作 .class 文件的二进制格式
// 使用访问者模式（Visitor Pattern）遍历字节码

// ASM 的核心组件：
// - ClassReader：读取 class 文件
// - ClassVisitor：访问类结构（接口、注解、字段、方法）
// - ClassWriter：生成 class 文件的输出

// ASM 示例：给类添加一个字段
public class AsmDemo {
    public static byte[] addField(String className) throws Exception {
        ClassReader cr = new ClassReader(className);
        ClassWriter cw = new ClassWriter(cr, ClassWriter.COMPUTE_MAXS);

        cr.accept(new ClassVisitor(Opcodes.ASM9, cw) {
            @Override
            public void visitEnd() {
                super.visitEnd();
                // 添加 private long timestamp 字段
                FieldVisitor fv = cv.visitField(
                    Opcodes.ACC_PRIVATE,
                    "timestamp",
                    "J",  // long 的类型描述符
                    null,
                    null);
                if (fv != null) fv.visitEnd();
            }
        }, 0);

        return cw.toByteArray();
    }
}

// ASM 的优势：
// 1. 速度极快（直接在字节码层面操作）
// 2. 内存占用小
// 3. 可以操作任意字节码细节
// 缺点：API 复杂，需要了解 JVM 指令集

// ASM 的应用：
// - CGLIB 底层使用 ASM
// - Spring 的 @Configuration 类代理
// - Mockito 的 mock 框架
// - Gradle 编译期字节码修改
```

### 3.2 Javassist

```java
// Javassist（Java Programming Assistant）
// 提供源码级别的 API，不需要了解字节码指令

// 使用 Javassist 创建类：
import javassist.*;

public class JavassistDemo {
    public static void main(String[] args) throws Exception {
        ClassPool pool = ClassPool.getDefault();

        // 创建一个新类
        CtClass cc = pool.makeClass("com.example.DynamicClass");

        // 添加字段
        CtField field = new CtField(CtClass.longType, "timestamp", cc);
        field.setModifiers(Modifier.PRIVATE);
        cc.addField(field);
        cc.addMethod(CtNewMethod.getter("getTimestamp", field));
        cc.addMethod(CtNewMethod.setter("setTimestamp", field));

        // 添加方法
        CtMethod method = CtNewMethod.make(
            "public void sayHello() { System.out.println(\"Hello!\"); }", cc);
        cc.addMethod(method);

        // 生成类
        Class<?> clazz = cc.toClass();
        Object obj = clazz.newInstance();
        clazz.getMethod("sayHello").invoke(obj);
    }
}

// Javassist 的优势：
// 1. 语法简单（源码级）
// 2. 学习成本低
// 3. 适合快速原型
// 缺点：速度比 ASM 慢，功能不如 ASM 灵活

// 应用场景：
// - MyBatis 的延迟加载
// - 热部署工具（JRebel 早期版本）
// - 测试框架（TestNG）
```

### 3.3 ByteBuddy

```java
// ByteBuddy（JDK 6+）—— 现代化字节码框架
// 目前 Spring Boot 3、Hibernate 6 等主流框架的默认字节码工具

// ByteBuddy 的特点：
// 1. 不需要理解字节码指令
// 2. 类型安全的 API（编译期检查）
// 3. 强大的类型描述系统（TypeDescription）
// 4. 支持 Java Agent（运行时 re-transform）

import net.bytebuddy.ByteBuddy;
import net.bytebuddy.implementation.FixedValue;
import net.bytebuddy.implementation.MethodDelegation;
import net.bytebuddy.matcher.ElementMatchers;

public class ByteBuddyDemo {
    public static void main(String[] args) throws Exception {
        // 1. 创建一个类
        Class<?> dynamicType = new ByteBuddy()
            .subclass(Object.class)
            .method(ElementMatchers.named("toString"))
            .intercept(FixedValue.value("Hello ByteBuddy!"))
            .make()
            .load(ByteBuddyDemo.class.getClassLoader())
            .getLoaded();

        Object obj = dynamicType.newInstance();
        System.out.println(obj.toString());  // "Hello ByteBuddy!"

        // 2. 拦截方法
        Class<?> proxyType = new ByteBuddy()
            .subclass(UserService.class)
            .method(ElementMatchers.any())
            .intercept(MethodDelegation.to(new LogInterceptor()))
            .make()
            .load(UserService.class.getClassLoader())
            .getLoaded();

        UserService proxy = (UserService) proxyType.newInstance();
        proxy.addUser("Alice");
    }
}

// ByteBuddy 的优势：
// 1. API 优雅（流式 + 类型安全）
// 2. 强大的匹配器（方法名、注解、返回值等）
// 3. 支持 Java Agent
// 4. 活跃维护，现代框架全面采用
```

### 3.4 框架对比

```java
// ┌────────────┬──────────────┬──────────────┬────────────────┐
// │            │ ASM          │ Javassist    │ ByteBuddy      │
// ├────────────┼──────────────┼──────────────┼────────────────┤
// │ 抽象级别   │ 字节码操作   │ 源码操作     │ 类型安全 API   │
// │ 学习曲线   │ 陡峭         │ 平缓         │ 平缓           │
// │ 性能       │ 极快         │ 中           │ 快             │
// │ 灵活性     │ 极高         │ 中           │ 高             │
// │ 依赖大小   │ 小           │ 中           │ 中             │
// │ 现代框架   │ CGLIB 底层   │ MyBatis      │ Spring/Hibernate│
// │ 推荐指数   │ ⭐⭐⭐       │ ⭐⭐⭐       │ ⭐⭐⭐⭐⭐      │
// └────────────┴──────────────┴──────────────┴────────────────┘

// 选型建议：
// 1. 新项目：首选 ByteBuddy（Spring Boot 3 的选择）
// 2. 需要源码级简单生成：Javassist
// 3. 极致的性能或精细控制：ASM
```

## 4. Spring AOP 代理实现

### 4.1 代理创建策略

```java
// Spring AOP 使用动态代理实现切面编程
// 创建代理的策略（org.springframework.aop.framework.DefaultAopProxyFactory）：

public class DefaultAopProxyFactory implements AopProxyFactory {

    @Override
    public AopProxy createAopProxy(AdvisedSupport config) throws AopConfigException {
        // 三种条件使用 CGLIB：
        // 1. optimize=true（优化模式，Spring 通常不开启）
        // 2. proxy-target-class=true（强制 CGLIB）
        // 3. 目标类没有实现接口
        if (config.isOptimize() || config.isProxyTargetClass()
            || hasNoUserSuppliedProxyInterfaces(config)) {
            return new CglibAopProxy(config);     // CGLIB 代理
        }
        return new JdkDynamicAopProxy(config);    // JDK 动态代理
    }

    private boolean hasNoUserSuppliedProxyInterfaces(AdvisedSupport config) {
        Class<?>[] interfaces = config.getProxiedInterfaces();
        return interfaces.length == 0;
        // 注意：如果目标类实现了 Spring 自身的回调接口，不算"用户提供的接口"
    }
}

// Spring Boot 2.0+ 默认使用 CGLIB（proxy-target-class=true）
// 因为 Spring Boot 推荐使用实现而非接口编程
// 可以通过 spring.aop.proxy-target-class=false 改为 JDK 代理
```

### 4.2 自调用问题

```java
// Spring AOP 的自调用问题（同一个类中方法调用不会走代理）：

@Service
public class UserService {
    @Transactional
    public void addUser(String name) {
        // 开启事务...
        saveUser(name);  // ❌ 自调用，事务不生效！
    }

    @Transactional
    public void saveUser(String name) {
        // 事务操作...
    }
}

// 为什么自调用不生效？
// proxy.addUser("Alice") → AOP 代理 → 目标.addUser("Alice")
//                                    → this.saveUser("Alice") ← this 是目标对象，不是代理

// 解决方案：

// 方案 1：注入自身（循环依赖，不推荐）
@Service
public class UserService {
    @Autowired
    private UserService self;  // 实际上是代理对象

    @Transactional
    public void addUser(String name) {
        self.saveUser(name);  // 通过代理调用
    }
}

// 方案 2：使用 AopContext（需要 exposeProxy=true）
@Service
public class UserService {
    @Transactional
    public void addUser(String name) {
        ((UserService) AopContext.currentProxy()).saveUser(name);
    }
}
// 配置：@EnableAspectJAutoProxy(exposeProxy = true)

// 方案 3：提取到另一个 Bean（推荐）
@Service
public class UserService {
    @Autowired
    private UserSaveService userSaveService;

    @Transactional
    public void addUser(String name) {
        userSaveService.saveUser(name);  // 另一个 Bean，必然是代理
    }
}

// 方案 4：在方法内部调用自己（重构代码，让外层逻辑不需要自调用）
```

### 4.3 @Aspect 注解解析

```java
// Spring AOP 的底层代理实现
// 当 Spring 检测到 @Aspect 注解时，创建 Advisor 链

// @Around 的代理过程：
// proxy.addUser("Alice")
//   → JdkDynamicAopProxy.invoke(proxy, method, args)
//     → 获取目标方法的所有 Advisor（MethodInterceptor 链）
//     → 创建 ReflectiveMethodInvocation（责任链）
//     → 依次调用拦截器
//       → 执行前置通知（@Before）
//       → 执行环绕通知（@Around）
//       → 执行目标方法
//       → 执行返回通知（@AfterReturning）
//       → 执行后置通知（@After）
//       → 执行异常通知（@AfterThrowing）

// 责任链执行顺序（默认）：
// Around → Before → 目标方法 → AfterReturning(正常) / AfterThrowing(异常)
//         → After(最终)
```

## 5. 反射进阶

### 5.1 MethodHandle

```java
// MethodHandle（JDK 7+）是 JVM 级别的动态语言支持
// 与反射 Method 的对比：
// - 反射是 Java 语言层面的模拟（Method 对象）
// - MethodHandle 是 JVM 指令层面的（可以直接内联）
// - 反射需要安全检查，MethodHandle 不需要
// - MethodHandle 类型严格（WrongMethodTypeException）

import java.lang.invoke.*;

public class MethodHandleDemo {

    public void hello(String name) {
        System.out.println("Hello, " + name);
    }

    public static void main(String[] args) throws Throwable {
        MethodHandles.Lookup lookup = MethodHandles.lookup();

        // 1. 查找方法
        MethodType mt = MethodType.methodType(void.class, String.class);
        MethodHandle mh = lookup.findVirtual(
            MethodHandleDemo.class, "hello", mt);

        // 2. 调用
        MethodHandleDemo demo = new MethodHandleDemo();
        mh.invoke(demo, "Alice");      // "Hello, Alice"
        mh.bindTo(demo).invoke("Bob"); // "Hello, Bob"

        // 3. invoke 与 invokeExact
        mh.invoke(demo, "Charlie");       // 宽松类型匹配（自动转型）
        // mh.invokeExact(demo, "Charlie"); // 严格类型匹配（必须精确）

        // 4. MethodHandle 的类型转换
        MethodHandle mh2 = mh.asType(mh.type()
            .changeReturnType(String.class));
        // 转换返回类型

        // 5. 组合
        MethodHandle mh3 = MethodHandles.filterReturnValue(
            mh, MethodHandles.constant(String.class, "Done"));

        // MethodHandle 的应用：
        // - LambdaMetafactory（Lambda 表达式底层）
        // - Jackson、Gson 等序列化框架
        // - 脚本引擎（Nashorn/GraalVM）
    }
}
```

### 5.2 MethodHandle 与反射的对比

```java
// 性能对比：
// JDK 7：MethodHandle 比反射快约 20-30%
// JDK 8：反射 inflate 优化后，两者差距缩小
// JDK 9+：MethodHandle 再次领先（尤其是 VarHandle）

// 功能对比：
// ┌──────────────┬──────────────────┬──────────────────────┐
// │              │ Method           │ MethodHandle         │
// ├──────────────┼──────────────────┼──────────────────────┤
// │ 所属层级     │ Java 反射 API    │ JVM 指令层面         │
// │ 安全检查     │ 每次调用检查     │ 创建时检查           │
// │ 类型检查     │ 运行时检查       │ 编译期（invokeExact） │
// │ 内联         │ 不可内联         │ 可内联               │
// │ 访问控制     │ setAccessible    │ Lookup 控制          │
// │ 灵活性       │ 高（通用）       │ 高（专用）           │
// └──────────────┴──────────────────┴──────────────────────┘

// 选型建议：
// - 通用反射操作：反射（简单、熟悉）
// - 性能敏感的动态调用：MethodHandle
// - 字段原子操作：VarHandle（JDK 9+）
// - 动态创建回调：LambdaMetafactory
```

### 5.3 VarHandle（JDK 9+）

```java
// VarHandle 替代 Unsafe 的部分功能
// 提供：字段的原子操作、内存屏障、数组操作

// VarHandle 的功能：
// 1. get/set：读写
// 2. getVolatile/setVolatile：volatile 读写
// 3. getOpaque/setOpaque：有序但不保证可见性
// 4. compareAndSet：CAS
// 5. getAndSet：获取并设置
// 6. getAndAdd：获取并增加

public class VarHandleDemo {
    private volatile int count = 0;

    private static final VarHandle COUNT;

    static {
        try {
            COUNT = MethodHandles.lookup()
                .findVarHandle(VarHandleDemo.class, "count", int.class);
        } catch (Exception e) {
            throw new Error(e);
        }
    }

    public void increment() {
        // CAS 操作
        int expected;
        do {
            expected = (int) COUNT.getVolatile(this);
        } while (!COUNT.compareAndSet(this, expected, expected + 1));
    }

    public int getCount() {
        return (int) COUNT.getVolatile(this);
    }

    // VarHandle 相比 AtomicInteger 的优势：
    // 1. 不需要创建 AtomicInteger 对象
    // 2. 可以操作任何 volatile 字段
    // 3. 支持更丰富的内存排序语义
}
```

### 5.4 invokedynamic 与 LambdaMetafactory

```java
// invokedynamic（JDK 7）是 Java 最复杂的字节码指令
// 是 Lambda 表达式（JDK 8）的底层实现机制

// Lambda 表达式的编译：
// 我们写的代码：
Runnable r = () -> System.out.println("Hello");

// 编译后的字节码等效（简化）：
// invokedynamic #run, bootstrap = LambdaMetafactory.metafactory()
//   → 返回一个 CallSite，绑定到 Runnable 的实现

// LambdaMetafactory 的作用：
// 在运行时生成目标函数式接口的实现
// 比匿名内部类更好的性能（不需要生成额外的类文件）

// 手动使用 LambdaMetafactory：
public class LambdaMetaFactoryDemo {
    public static void main(String[] args) throws Throwable {
        // 目标接口的方法类型
        MethodType funType = MethodType.methodType(void.class, String.class);
        // 实现的实现方法类型
        MethodType implType = MethodType.methodType(void.class, String.class);

        MethodHandles.Lookup lookup = MethodHandles.lookup();
        MethodHandle impl = lookup.findStatic(
            LambdaMetaFactoryDemo.class, "print", implType);

        // 创建 CallSite
        CallSite site = LambdaMetafactory.metafactory(
            lookup,
            "accept",                    // 函数式接口的方法名
            MethodType.methodType(Consumer.class),  // 工厂类型
            funType,                     // 签名
            impl,                        // 实现方法句柄
            funType                      // 运行时签名
        );

        // 获取 Consumer 实例
        Consumer<String> consumer = (Consumer<String>) site.getTarget().invoke();
        consumer.accept("Hello Lambda!");  // 输出 "Hello Lambda!"
    }

    public static void print(String s) {
        System.out.println(s);
    }
}

// invokedynamic 的优势：
// 1. 延迟绑定：启动时不会生成代码，在第一次调用时才生成
// 2. 轻量：不需要生成 .class 文件
// 3. 内联友好：JIT 可以更好地优化
// 4. 动态类型：支持动态语言（Nashorn/GraalVM）
```

### 5.5 模块化下的反射限制

```java
// JDK 9+ 模块系统对反射的限制：

// 传统 JDK 8 及之前：
// setAccessible(true) 可以访问任意类的私有成员

// JDK 9+：
// 如果目标类在某个模块中，但没有对调用者模块 open/export
// setAccessible(true) 会抛 InaccessibleObjectException

// 解决方法：

// 1. 模块提供方开放（module-info.java）：
module com.example.core {
    exports com.example.core.api;          // 导出包（可访问 public 类型）
    opens com.example.core.internal;        // 开放包（允许反射访问私有成员）
    opens com.example.core.model to         // 定向开放
        com.example.orm;
}

// 2. 调用方使用 JVM 参数（临时方案，不推荐生产）：
// --add-opens java.base/java.lang=ALL-UNNAMED
// --add-exports java.base/sun.security.x509=ALL-UNNAMED

// 3. 使用 Unsafe（不推荐，JDK 9+ 也限制了 Unsafe）

// 4. Spring/MyBatis 等框架的适配：
// Spring 在 JDK 9+ 使用 `--add-opens` 自动配置
// 通过 `SpringProperties` 检测 JDK 版本自动处理

// 影响最大的场景：
// - 序列化框架（Jackson、Gson、Fastjson）
// - ORM 框架（Hibernate、MyBatis）
// - 依赖注入框架（Spring、Guice）
// - 动态代理（CGLIB、ByteBuddy需要适配）
```

## 6. 面试题

### Q1：JDK 动态代理和 CGLIB 的区别？Spring AOP 用哪个？

```java
// JDK 动态代理：基于接口 + Proxy + InvocationHandler
// CGLIB：基于继承 + ASM 字节码 + MethodInterceptor

// Spring AOP 的选择逻辑（DefaultAopProxyFactory）：
// 1. 目标类实现了接口 → JDK 动态代理（默认）
// 2. 目标类没有接口 → CGLIB
// 3. proxy-target-class=true → CGLIB

// Spring Boot 2.0+ 默认 CGLIB（proxy-target-class=true）
// 原因：Spring Boot 推荐实现而非接口编程

// 性能对比（JDK 8+）：
// JDK 代理调用性能 ≈ CGLIB（JDK 代理略优）
// CGLIB 代理类创建性能比 JDK 好（不需要编译阶段）
```

### Q2：CGLIB 能代理 final 类和方法吗？

```java
// 不能。
// CGLIB 通过生成目标类的子类来实现代理
// final 类不可继承 → 不能代理
// final 方法不可覆盖 → 不能代理
// static 方法属于类，不属于实例 → 不能代理
// private 方法对子类不可见 → 不能代理

// 如果尝试代理 final 类：
// Enhancer enhancer = new Enhancer();
// enhancer.setSuperclass(String.class);  // String 是 final
// → ❌ IllegalArgumentException: Cannot subclass final class java.lang.String
```

### Q3：Method.invoke 的性能为什么差？

```java
// Method.invoke 的性能开销主要来自：
// 1. 可变参数装箱：Object[] args 导致基本类型装箱
// 2. 安全检查：每次调用检查方法的访问权限
// 3. 类型检查：检查参数类型是否匹配
// 4. JIT 不优化：反射调用难以内联（直到 JDK 8 的 inflate 机制）
// 5. JNI 调用开销：Method.invoke 是 native 方法

// JDK 8 的优化：MethodAccessor.invoke
// 前 15 次调用使用 NativeMethodAccessor
// 超过阈值后生成 GeneratedMethodAccessor（Java 字节码版本）
// 性能接近直接调用
// -Dsun.reflect.inflationThreshold=0 可以禁用延迟优化
```

### Q4：invokedynamic 比反射好在哪里？

```java
// 1. 启动时不生成任何代码，第一次调用时才生成
// 2. JIT 可以内联 invokedynamic 的调用（反射不行）
// 3. 不需要安全检查（权限在引导方法中确定）
// 4. 更轻量：不需要 Method 对象
// 5. 动态类型：方法签名可以在运行时确定

// Lambda 表达式用 invokedynamic 而不是匿名内部类的原因：
// 匿名内部类：每个 lambda 生成一个 .class 文件，加载成本高
// invokedynamic：运行时动态生成，更轻量，JIT 更友好
```

### Q5：如何破坏单例模式（反射角度）？

```java
// 反射破坏单例的几种方式：

// 1. 反射调用私有构造器
Constructor<Singleton> con = Singleton.class.getDeclaredConstructor();
con.setAccessible(true);
Singleton s2 = con.newInstance();  // 创建新实例

// 2. 反射修改 static 字段
Field instance = Singleton.class.getDeclaredField("INSTANCE");
instance.setAccessible(true);
instance.set(null, null);  // 破坏单例

// 3. 序列化破坏（readObject 创建新实例）
// 解决方案：添加 readResolve() 方法

// 最安全的防御：枚举单例
// 反射不能创建枚举实例（IllegalArgumentException）
// 序列化也是安全的（Enum 的序列化特殊处理）
```
