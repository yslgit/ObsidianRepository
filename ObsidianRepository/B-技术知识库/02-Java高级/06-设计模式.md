### 核心概念
**设计模式**是软件工程中经过验证的、可重复使用的解决方案。**GoF 23 种模式**分为创建型（如何创建对象）、结构型（如何组合类/对象）和行为型（如何交互）。核心是**面向接口编程**和**优先组合而非继承**。**SOLID 原则**是评价和选择设计模式的根本准则。

### 常见误区
❌ **误区 1**：模式越多越好
✅ **真相**：过度使用设计模式会导致代码复杂化。KISS 原则优先，模式本质是解决特定问题的工具，不是目标。

❌ **误区 2**：单例模式就是全局变量
✅ **真相**：单例的职责是保证对象唯一性并控制访问，不是全局状态容器。滥用单例会导致隐式依赖和测试困难。

❌ **误区 3**：工厂模式和抽象工厂是一回事
✅ **真相**：工厂方法（一个方法创建一种产品）和抽象工厂（一个工厂创建产品族）是两个不同模式，解决不同层次的问题。

❌ **误区 4**：设计模式是固定不变的模板
✅ **真相**：模式是思想而非代码模板。函数式编程诞生后，策略模式、命令模式、观察者模式都可以用 Lambda 简化。

### 实战建议
1. **优先用组合而非继承**：继承破坏封装，组合更灵活
2. **面向接口编程**：接口是最常用的抽象方式
3. **Lambda 简化模式**：策略→`Function`/`Consumer`、观察者→`Consumer`回调、命令→`Runnable`
4. **不要为模式而模式**：先把代码写清楚，再看是否匹配模式
5. **Spring 中模式无处不在**：多观察 Spring 源码中的模式应用

## 0. 设计原则

### SOLID 原则

```java
// 1. SRP（单一职责原则）
// 一个类只负责一个职责
// 反例：
class UserService {
    void addUser(User user) { /* 业务逻辑 */ }
    void sendEmail(String msg) { /* 邮件发送 */ }
    void exportToExcel() { /* 导出报表 */ }
}
// 正例：拆分多个类
class UserService { void addUser(User user) { } }
class EmailService { void sendEmail(String msg) { } }
class ExcelExporter { void exportToExcel() { } }

// 2. OCP（开闭原则）
// 对扩展开放，对修改关闭
// 正例：策略模式 + 接口
interface PaymentStrategy {
    void pay(double amount);
}
// 新增支付方式时不需要修改现有代码，只需新增实现类

// 3. LSP（里氏替换原则）
// 子类可以替换父类而不影响程序正确性
// 反例：正方形不能替换长方形
class Rectangle {
    int w, h;
    void setWidth(int w) { this.w = w; }
    void setHeight(int h) { this.h = h; }
}
class Square extends Rectangle {
    void setWidth(int w) { super.setWidth(w); super.setHeight(w); }
    void setHeight(int h) { super.setWidth(h); super.setHeight(h); }
}
// 如果之前代码设置了宽高但不相等，Square 会破坏预期

// 4. ISP（接口隔离原则）
// 客户端不应依赖它不需要的接口方法
// 反例：胖接口
interface Worker {
    void work();
    void eat();
    void sleep();
}
// 正例：细分接口
interface Workable { void work(); }
interface Eatable { void eat(); }
interface Sleepable { void sleep(); }

// 5. DIP（依赖倒置原则）
// 依赖抽象而非具体实现
// 反例：
class UserService {
    private MySqlRepository repo = new MySqlRepository();  // 依赖具体
}
// 正例：
class UserService {
    private final UserRepository repo;  // 依赖抽象（接口）
    UserService(UserRepository repo) { this.repo = repo; }
}

// 6. LoD（迪米特法则/最少知识原则）
// 一个对象应该对其他对象有尽可能少的了解
// 反例：
order.getCustomer().getAddress().getCity();
// 正例：order.getCustomerCity();
// 不要链式调用访问深层对象的方法
```

## 1. 创建型模式

### 1.1 单例模式（Singleton）

#### 枚举单例（最推荐）

```java
// 最安全的单例实现
// 1. 线程安全（JVM 保证枚举常量的创建是原子的）
// 2. 防反射（枚举构造器反射会抛 IllegalArgumentException）
// 3. 防序列化破坏（Enum 的序列化特殊处理）
public enum Singleton {
    INSTANCE;

    private String config;

    public void setConfig(String config) {
        this.config = config;
    }

    public String getConfig() {
        return config;
    }

    public void doSomething() {
        System.out.println("Singleton doing something");
    }
}
// 使用：Singleton.INSTANCE.doSomething();
```

#### 静态内部类（懒加载 + 线程安全）

```java
public class Singleton {
    private Singleton() { }

    // 静态内部类在 Singleton 加载时不会初始化
    // 只有在调用 getInstance() 时才加载 → 懒加载
    private static class Holder {
        static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;  // 触发 Holder 的加载和初始化
    }
}
```

#### 双重检查锁定（DCL）

```java
public class Singleton {
    // volatile 禁止指令重排序
    // new Singleton() 的步骤：
    // 1. 分配内存空间
    // 2. 初始化对象
    // 3. 将引用指向内存空间
    // 如果不加 volatile，步骤 2 和 3 可能被重排
    private static volatile Singleton instance;

    private Singleton() { }

    public static Singleton getInstance() {
        if (instance == null) {                    // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) {            // 第二次检查
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

#### 单例模式的应用

```java
// JDK 中的应用：
// Runtime.getRuntime() → 单例（DCL）
// Spring Bean 默认 scope = singleton
// Logger 通常使用单例

// 使用场景：
// - 配置管理中心（ConfigManager）
// - 数据库连接池（ConnectionPool）—— 注意这里通常还是使用 Spring 管理的单例 Bean
// - 线程池（如 Executors.newSingleThreadExecutor()）
```

### 1.2 工厂模式

#### 简单工厂（不是 GoF 模式，但最常用）

```java
public class PaymentFactory {
    public static Payment create(String type) {
        switch (type) {
            case "alipay": return new Alipay();
            case "wechat": return new WechatPay();
            case "credit": return new CreditCardPay();
            default: throw new IllegalArgumentException("Unknown type: " + type);
        }
    }
}
// 缺点：违反 OCP，新增支付方式需要修改工厂
```

#### 工厂方法

```java
// 定义一个创建对象的接口，让子类决定实例化哪个类
interface PaymentFactory {
    Payment create();
}

class AlipayFactory implements PaymentFactory {
    @Override
    public Payment create() {
        return new Alipay();
    }
}

class WechatPayFactory implements PaymentFactory {
    @Override
    public Payment create() {
        return new WechatPay();
    }
}

// 客户端使用：
PaymentFactory factory = new AlipayFactory();
// 通过多态，可以替换 factory 的实现
Payment payment = factory.create();

// JDK 中的应用：
// Collection.iterator() → 工厂方法
// URL.openConnection() → 工厂方法
// Class.newInstance() → 本质是工厂方法
```

#### 抽象工厂

```java
// 创建产品族（一组相关/依赖的对象）
// 与工厂方法的区别：
// 工厂方法：一个工厂创建一种产品
// 抽象工厂：一个工厂创建一族产品

// 产品族：UI 主题
interface Button { void render(); }
interface Checkbox { void render(); }

// 抽象工厂：创建 UI 产品族
interface UIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// 具体工厂 1：Windows 主题
class WindowsFactory implements UIFactory {
    @Override
    public Button createButton() { return new WindowsButton(); }
    @Override
    public Checkbox createCheckbox() { return new WindowsCheckbox(); }
}

// 具体工厂 2：Mac 主题
class MacFactory implements UIFactory {
    @Override
    public Button createButton() { return new MacButton(); }
    @Override
    public Checkbox createCheckbox() { return new MacCheckbox(); }
}

// 客户端：只需要知道是 Windows 还是 Mac 主题
UIFactory factory = new WindowsFactory();
Button button = factory.createButton();       // WindowsButton
Checkbox checkbox = factory.createCheckbox(); // WindowsCheckbox

// JDK 中的应用：
// DocumentBuilderFactory.newInstance() → 抽象工厂
// javax.xml.parsers 包

// MyBatis 中的应用：
// SqlSessionFactory → 抽象工厂
// 生产 SqlSession、Mapper、Executor 等
```

### 1.3 建造者模式

```java
// 用于构建复杂对象，分离对象的构建和表示
// 核心：一部一步地构建，最后 build()

// Builder 模式的经典实现：
public class Computer {
    private String cpu;
    private String gpu;
    private int ram;
    private int storage;
    private boolean hasBluetooth;

    private Computer(Builder builder) {
        this.cpu = builder.cpu;
        this.gpu = builder.gpu;
        this.ram = builder.ram;
        this.storage = builder.storage;
        this.hasBluetooth = builder.hasBluetooth;
    }

    public static class Builder {
        private String cpu;
        private String gpu;
        private int ram;
        private int storage;
        private boolean hasBluetooth;

        public Builder cpu(String cpu) { this.cpu = cpu; return this; }
        public Builder gpu(String gpu) { this.gpu = gpu; return this; }
        public Builder ram(int ram) { this.ram = ram; return this; }
        public Builder storage(int storage) { this.storage = storage; return this; }
        public Builder bluetooth(boolean has) { this.hasBluetooth = has; return this; }

        public Computer build() {
            return new Computer(this);
        }
    }
}

// 使用：
Computer computer = new Computer.Builder()
    .cpu("Intel i7")
    .gpu("NVIDIA RTX 3080")
    .ram(32)
    .storage(512)
    .bluetooth(true)
    .build();

// 什么时候用 Builder 而不是构造器？
// 1. 参数过多（>4 个）
// 2. 参数有可选性
// 3. 参数类型相同（容易混淆顺序）
// 4. 参数有层级关系

// JDK 中的应用：
// StringBuilder.append() → 类似 Builder 模式
// Stream.builder()
// Optional 的工厂方法

// MyBatis 中的应用：
// SqlSessionFactoryBuilder → 解析配置并构建 SqlSessionFactory
// XMLConfigBuilder → 构建 Configuration 对象

// Lombok 的 @Builder 注解：
@Builder
public class User {
    private String name;
    private int age;
    private String email;
}
```

### 1.4 原型模式

```java
// 通过复制已有对象来创建新对象
// Java 中的 clone() 方法

// 浅拷贝（Object.clone() 默认）：
public class User implements Cloneable {
    private String name;
    private Address address;  // 引用类型

    @Override
    protected User clone() throws CloneNotSupportedException {
        return (User) super.clone();  // 浅拷贝：address 引用同一个对象
    }
}

// 深拷贝（需要手动拷贝引用类型）：
@Override
protected User clone() throws CloneNotSupportedException {
    User clone = (User) super.clone();
    clone.address = this.address.clone();  // 手动拷贝引用字段
    return clone;
}

// 原型模式的应用场景：
// 1. 对象创建成本高（如数据库查询结果）
// 2. 对象状态只有少量差异（原型 + 修改）
// 3. 避免构造器的复杂性

// 更推荐使用拷贝构造器（不使用 Cloneable）：
public class User {
    private String name;
    private Address address;

    public User(User other) {  // 拷贝构造器
        this.name = other.name;
        this.address = new Address(other.address);
    }
}

// 或者使用序列化实现深拷贝：
public User deepCopy() {
    try (ByteArrayOutputStream bos = new ByteArrayOutputStream();
         ObjectOutputStream oos = new ObjectOutputStream(bos)) {
        oos.writeObject(this);
        try (ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
             ObjectInputStream ois = new ObjectInputStream(bis)) {
            return (User) ois.readObject();
        }
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

## 2. 结构型模式

### 2.1 适配器模式

```java
// 将一个接口转换成客户端期望的另一个接口
// 解决接口不兼容问题

// 场景：老系统 Logger 接口需要适配新日志框架
interface OldLogger {
    void log(String msg);
}

// 新框架的日志接口
interface NewLogger {
    void debug(String msg);
    void info(String msg);
    void error(String msg);
}

// 对象适配器（组合）—— 推荐
class LoggerAdapter implements OldLogger {
    private final NewLogger newLogger;

    LoggerAdapter(NewLogger newLogger) {
        this.newLogger = newLogger;
    }

    @Override
    public void log(String msg) {
        newLogger.info(msg);  // 将旧接口的 log 映射到 info
    }
}

// 类适配器（继承）—— Java 不推荐（接口适配器还可以）
class LoggerAdapter2 extends Log4jLogger implements OldLogger {
    @Override
    public void log(String msg) {
        super.info(msg);
    }
}

// JDK 中的应用：
// Arrays.asList() → 数组适配为 List
// ReaderInputStream → Reader 适配为 InputStream
// List<> 到数组：list.toArray()

// Spring 中的应用：
// HandlerAdapter → 适配不同的 Controller 类型
// 各种 Adapter 类
```

### 2.2 装饰器模式

```java
// 动态地给对象添加额外的职责
// 比继承更灵活（不需要为每个功能组合创建子类）

// 核心：包装（Wrapper），递归组合

interface Coffee {
    double cost();
    String description();
}

class SimpleCoffee implements Coffee {
    @Override
    public double cost() { return 10.0; }

    @Override
    public String description() { return "咖啡"; }
}

// 抽象装饰器
abstract class CoffeeDecorator implements Coffee {
    protected final Coffee coffee;

    CoffeeDecorator(Coffee coffee) {
        this.coffee = coffee;
    }
}

// 具体装饰器
class MilkDecorator extends CoffeeDecorator {
    MilkDecorator(Coffee coffee) { super(coffee); }

    @Override
    public double cost() { return coffee.cost() + 3.0; }

    @Override
    public String description() { return coffee.description() + " + 牛奶"; }
}

class SugarDecorator extends CoffeeDecorator {
    SugarDecorator(Coffee coffee) { super(coffee); }

    @Override
    public double cost() { return coffee.cost() + 1.5; }

    @Override
    public String description() { return coffee.description() + " + 糖"; }
}

// 使用：
Coffee coffee = new SimpleCoffee();
coffee = new MilkDecorator(coffee);     // 咖啡 + 牛奶
coffee = new SugarDecorator(coffee);    // 咖啡 + 牛奶 + 糖
System.out.println(coffee.description() + " = ¥" + coffee.cost());

// JDK 中的应用：
// InputStream 体系 —— 装饰器模式的经典应用
// new BufferedInputStream(new FileInputStream("file.txt"));
// new GZIPInputStream(new FileInputStream("file.gz"));
// 每层装饰增加功能：缓存、压缩、加密等

// Collection 的 unmodifiableXXX、synchronizedXXX 也是装饰器
```

### 2.3 代理模式

```java
// 为另一个对象提供一个代理以控制对这个对象的访问

// 静态代理（与 JDK 动态代理的区别：编译期确定）
interface Image {
    void display();
}

// 真实主题
class RealImage implements Image {
    private final String filename;

    RealImage(String filename) {
        this.filename = filename;
        loadFromDisk();  // 初始化时加载（开销大）
    }

    private void loadFromDisk() {
        System.out.println("Loading " + filename + " from disk...");
    }

    @Override
    public void display() {
        System.out.println("Displaying " + filename);
    }
}

// 代理（延迟加载 + 缓存）
class ImageProxy implements Image {
    private final String filename;
    private RealImage realImage;  // 延迟加载

    ImageProxy(String filename) {
        this.filename = filename;
    }

    @Override
    public void display() {
        if (realImage == null) {
            realImage = new RealImage(filename);  // 第一次使用时才加载
        }
        realImage.display();
    }
}

// 代理模式的常见类型：
// 1. 远程代理：RPC、RMI 的 stub
// 2. 虚拟代理：延迟加载（如上面的图片加载）
// 3. 保护代理：访问控制
// 4. 智能引用：日志、性能监控

// JDK 中的应用（参考第 5 章动态代理部分）
// Spring AOP 也是代理模式
```

### 2.4 外观模式

```java
// 为子系统提供一个统一的入口（门面）
// 封装复杂的子系统交互

// 复杂的子系统
class OrderService { public void createOrder() { } }
class PaymentService { public void processPayment() { } }
class InventoryService { public void updateStock() { } }
class ShippingService { public void shipOrder() { } }

// 外观（门面）
class OrderFacade {
    private OrderService orderService = new OrderService();
    private PaymentService paymentService = new PaymentService();
    private InventoryService inventoryService = new InventoryService();
    private ShippingService shippingService = new ShippingService();

    public void placeOrder(Order order) {
        orderService.createOrder(order);
        paymentService.processPayment(order);
        inventoryService.updateStock(order);
        shippingService.shipOrder(order);
    }
}

// 使用：客户端只看到 OrderFacade.placeOrder()
// 不需要知道内部调用了 4 个服务

// JDK 中的应用：

// java.net.URL → 封装了多个网络协议的交互

// 最典型的：SLF4J
// LoggerFactory.getLogger() → 外观模式
// 底层可以替换为 Logback、Log4j、Log4j2、JUL 等
```

### 2.5 桥接模式

```java
// 将抽象部分与实现部分分离，使它们可以独立变化
// 解决"类爆炸"问题：如果有 M 种抽象和 N 种实现，继承需要 M×N 个类，桥接只需要 M+N 个类

// 抽象部分
abstract class Shape {
    protected Color color;  // 组合颜色（桥接）

    Shape(Color color) {
        this.color = color;
    }

    abstract String draw();
}

// 具体抽象
class Circle extends Shape {
    Circle(Color color) { super(color); }

    @Override
    String draw() {
        return "圆形, " + color.fill();
    }
}

class Square extends Shape {
    Square(Color color) { super(color); }

    @Override
    String draw() {
        return "方形, " + color.fill();
    }
}

// 实现部分
interface Color {
    String fill();
}

class Red implements Color {
    @Override
    public String fill() { return "红色"; }
}

class Blue implements Color {
    @Override
    public String fill() { return "蓝色"; }
}

// 使用：2 × 2 = 4 种组合
Shape redCircle = new Circle(new Red());    // 圆形, 红色
Shape blueSquare = new Square(new Blue());  // 方形, 蓝色

// JDK 中的应用：
// JDBC 驱动：DriverManager（抽象）←→ 具体驱动实现（MySQL、PostgreSQL）
// Java 集合框架：List/Set（抽象）←→ ArrayList/LinkedList（实现）

// 其实 JDBC 本质上是桥接 + 策略模式
```

### 2.6 组合模式

```java
// 将对象组合成树形结构以表示"部分-整体"的层次结构
// 使得用户对单个对象和组合对象的使用具有一致性

// 组件（Component）接口
interface FileSystemNode {
    void show(String prefix);
    int getSize();
}

// 叶子节点：文件
class File implements FileSystemNode {
    private String name;
    private int size;

    File(String name, int size) { this.name = name; this.size = size; }

    @Override
    public void show(String prefix) {
        System.out.println(prefix + "📄 " + name + " (" + size + "B)");
    }

    @Override
    public int getSize() { return size; }
}

// 组合节点：目录
class Directory implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children = new ArrayList<>();

    Directory(String name) { this.name = name; }

    void add(FileSystemNode node) { children.add(node); }

    @Override
    public void show(String prefix) {
        System.out.println(prefix + "📁 " + name + "/");
        for (FileSystemNode child : children) {
            child.show(prefix + "  ");
        }
    }

    @Override
    public int getSize() {
        return children.stream().mapToInt(FileSystemNode::getSize).sum();
    }
}

// 使用：
Directory root = new Directory("root");
root.add(new File("readme.txt", 100));
Directory src = new Directory("src");
src.add(new File("Main.java", 200));
src.add(new File("Util.java", 150));
root.add(src);

root.show("");
// 📁 root/
//   📄 readme.txt (100B)
//   📁 src/
//     📄 Main.java (200B)
//     📄 Util.java (150B)

// JDK 中的应用：
// java.awt.Container 和 java.awt.Component
// javax.faces.component.UIComponent
// 文件系统操作（Path 体系）
// HashMap 的 Node 和 TreeNode（组合 + 装饰）
```

### 2.7 享元模式

```java
// 通过共享技术支持大量细粒度对象
// 主要用于减少创建对象的数量，节省内存

// 享元对象
class ChessPiece {
    private final String color;  // 内部状态（不变、可共享）
    // 注意：color 不放在 ChessPiece 内部也行，但为了演示享元，放在这里

    ChessPiece(String color) { this.color = color; }

    // 外部状态（变化、不可共享）由客户端传入
    public void display(int x, int y) {
        System.out.println(color + "棋子在 (" + x + ", " + y + ")");
    }
}

// 享元工厂
class ChessPieceFactory {
    private static final Map<String, ChessPiece> CACHE = new HashMap<>();

    public static ChessPiece getChessPiece(String color) {
        // 如果有缓存的棋子，直接返回
        // 没有则创建
        return CACHE.computeIfAbsent(color, ChessPiece::new);
    }

    public static int getObjectCount() {
        return CACHE.size();
    }
}

// 使用（比如围棋，361 个位置，但只有黑白两种棋子）
class GoGame {
    public static void main(String[] args) {
        // 即使有 361 个棋子，也只创建 2 个 ChessPiece 对象
        for (int i = 0; i < 19; i++) {
            for (int j = 0; j < 19; j++) {
                ChessPiece piece = ChessPieceFactory.getChessPiece(
                    (i + j) % 2 == 0 ? "黑" : "白");
                piece.display(i, j);
            }
        }
        System.out.println("Total objects: " + ChessPieceFactory.getObjectCount());  // 2
    }
}

// 内部状态：可共享，存储在享元对象中（棋子的颜色）
```

### 3.1 策略模式

```java
// 定义一系列算法，把它们封装起来，并且可以互相替换
// 函数式编程下：策略 ≈ Function/Lambda

// 传统实现
interface DiscountStrategy {
    double applyDiscount(double price);
}

class NoDiscount implements DiscountStrategy {
    @Override
    public double applyDiscount(double price) { return price; }
}

class PercentageDiscount implements DiscountStrategy {
    private final double percent;

    PercentageDiscount(double percent) {
        this.percent = percent;
    }

    @Override
    public double applyDiscount(double price) {
        return price * (1 - percent / 100);
    }
}

class FixedDiscount implements DiscountStrategy {
    private final double amount;

    FixedDiscount(double amount) { this.amount = amount; }

    @Override
    public double applyDiscount(double price) {
        return Math.max(0, price - amount);
    }
}

// 上下文
class PriceCalculator {
    private DiscountStrategy strategy;

    PriceCalculator(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    public void setStrategy(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    public double calculate(double price) {
        return strategy.applyDiscount(price);
    }
}

// 函数式（Lambda 简化）：
PriceCalculator calculator = new PriceCalculator(price -> price);  // 无折扣
calculator.setStrategy(price -> price * 0.8);  // 8 折
calculator.setStrategy(price -> Math.max(0, price - 10));  // 减 10
```

### 3.2 模板方法模式

```java
// 定义一个操作的骨架，将具体步骤延迟到子类实现
// 核心：不变的部分放在父类，变化的部分让子类实现

// 模板方法
abstract class AbstractDataProcessor {
    // 模板方法（final：子类不能修改骨架）
    public final void process() {
        readData();
        validateData();
        processData();
        saveData();
        cleanup();
    }

    // 抽象方法——子类必须实现
    protected abstract void readData();
    protected abstract void processData();

    // 钩子方法（可选覆盖）
    protected void validateData() { }  // 默认不做验证
    protected void cleanup() { }       // 默认不做清理

    // 具体方法——所有子类共享
    private void saveData() {
        System.out.println("Saving to database...");
    }
}

class CsvDataProcessor extends AbstractDataProcessor {
    @Override
    protected void readData() {
        System.out.println("Reading CSV file...");
    }

    @Override
    protected void validateData() {
        System.out.println("Validating CSV data...");
    }

    @Override
    protected void processData() {
        System.out.println("Processing CSV data...");
    }
}

// 使用：
AbstractDataProcessor processor = new CsvDataProcessor();
processor.process();
// 输出：
// Reading CSV file...
// Validating CSV data...
// Processing CSV data...
// Saving to database...

// JDK 中的应用：
// InputStream.read() → 模板方法
// AbstractList.addAll() → 调用 add() 模板方法
// HttpServlet.doGet()/doPost() → 模板方法（service 是模板，doGet 是钩子）

// Spring 中的应用：
// JdbcTemplate.query() → 模板方法
// RestTemplate.execute() → 模板方法
// AbstractApplicationContext.refresh() → 经典模板方法
```

### 3.3 观察者模式

```java
// 定义对象间一对多的依赖关系，当被观察者状态变化时通知所有观察者

// 函数式简化：观察者 ≈ Consumer 回调

// 传统实现
interface Observer {
    void update(String event);
}

// JDK 也有 java.util.Observer 和 Observable，但已经 Deprecated

class ConcreteSubject {
    private List<Observer> observers = new ArrayList<>();
    private String state;

    public void attach(Observer observer) {
        observers.add(observer);
    }

    public void detach(Observer observer) {
        observers.remove(observer);
    }

    public void setState(String state) {
        this.state = state;
        notifyObservers(state);
    }

    private void notifyObservers(String event) {
        for (Observer observer : observers) {
            observer.update(event);
        }
    }
}

// 函数式（Consumer 简化）：
class EventBus {
    private List<Consumer<String>> listeners = new ArrayList<>();

    public void register(Consumer<String> listener) {
        listeners.add(listener);
    }

    public void publish(String event) {
        listeners.forEach(l -> l.accept(event));
    }
}

// JDK 中的应用：
// java.util.Observer/Observable（已过时）
// javax.swing.event 包（Swing 事件）
// java.util.EventListener
// PropertyChangeListener

// Spring 中的应用：
// ApplicationListener/ApplicationEvent → 事件驱动
// @EventListener 注解

// Guava EventBus → 观察者模式的高级实现
```

### 3.4 责任链模式

```java
// 将请求沿着链传递，每个处理器可以选择处理或传递给下一个
// JDK 中的 Filter、Netty 的 ChannelPipeline 都是责任链

abstract class Handler {
    protected Handler next;

    public Handler setNext(Handler next) {
        this.next = next;
        return next;  // 返回 next 方便链式调用
    }

    public abstract void handle(String request);

    protected void next(String request) {
        if (next != null) {
            next.handle(request);
        }
    }
}

class AuthHandler extends Handler {
    @Override
    public void handle(String request) {
        if ("admin".equals(request)) {
            System.out.println("Auth passed");
            next(request);  // 继续下一个
        } else {
            System.out.println("Auth failed: " + request);
            // 不调用 next，链中断
        }
    }
}

class LogHandler extends Handler {
    @Override
    public void handle(String request) {
        System.out.println("Logging: " + request);
        next(request);  // 继续
    }
}

class ValidationHandler extends Handler {
    @Override
    public void handle(String request) {
        if (request != null && !request.isEmpty()) {
            System.out.println("Validation passed");
            next(request);
        } else {
            System.out.println("Validation failed: empty request");
        }
    }
}

// 使用：
Handler chain = new AuthHandler();
chain.setNext(new LogHandler())
     .setNext(new ValidationHandler());
// 等价于：AuthHandler → LogHandler → ValidationHandler

chain.handle("admin");
// Auth passed
// Logging: admin
// Validation passed

// JDK/框架中的应用：
// javax.servlet.Filter → doFilter() 链
// Netty ChannelPipeline → ChannelHandler 链
// MyBatis Plugin → InterceptorChain
// Spring AOP → AdvisorChain
```

### 3.6 迭代器模式

```java
// 提供一种顺序访问聚合对象元素的方法，而不暴露内部表示

// JDK 已经内置 Iterator 接口，一般不需要自己实现

// 自定义迭代器场景：
class MyList<T> implements Iterable<T> {
    private T[] elements;

    MyList(T[] elements) { this.elements = elements; }

    @Override
    public Iterator<T> iterator() {
        return new Iterator<T>() {
            private int index = 0;

            @Override
            public boolean hasNext() {
                return index < elements.length;
            }

            @Override
            public T next() {
                if (!hasNext()) throw new NoSuchElementException();
                return elements[index++];
            }
        };
    }
}

// 使用：
MyList<String> list = new MyList<>(new String[]{"A", "B", "C"});
for (String s : list) {
    System.out.println(s);
}

// JDK 中的应用：
// 所有 Collection 的实现都提供了 iterator()
// 正是迭代器模式让 for-each 成为可能
```

### 3.7 状态模式

```java
// 允许对象在内部状态改变时改变其行为
// 状态模式 vs 策略模式：状态是自然的切换（状态机），策略是人为的选择

// 订单状态机
interface OrderState {
    void pay(OrderContext context);
    void ship(OrderContext context);
    void confirm(OrderContext context);
}

class NewOrderState implements OrderState {
    @Override
    public void pay(OrderContext context) {
        System.out.println("支付成功");
        context.setState(new PaidOrderState());
    }

    @Override
    public void ship(OrderContext context) {
        System.out.println("未支付不能发货");
    }

    @Override
    public void confirm(OrderContext context) {
        System.out.println("未支付的订单不能确认收货");
    }
}

class PaidOrderState implements OrderState {
    @Override
    public void pay(OrderContext context) {
        System.out.println("已经支付，不能重复支付");
    }

    @Override
    public void ship(OrderContext context) {
        System.out.println("发货成功");
        context.setState(new ShippedOrderState());
    }

    @Override
    public void confirm(OrderContext context) {
        System.out.println("未发货不能确认收货");
    }
}

class ShippedOrderState implements OrderState {
    @Override
    public void pay(OrderContext context) { System.out.println("已支付"); }

    @Override
    public void ship(OrderContext context) { System.out.println("已发货"); }

    @Override
    public void confirm(OrderContext context) {
        System.out.println("确认收货成功");
        context.setState(new CompletedOrderState());
    }
}

class CompletedOrderState implements OrderState {
    @Override
    public void pay(OrderContext context) { System.out.println("已完成"); }

    @Override
    public void ship(OrderContext context) { System.out.println("已完成"); }

    @Override
    public void confirm(OrderContext context) { System.out.println("已完成"); }
}

class OrderContext {
    private OrderState state = new NewOrderState();

    void setState(OrderState state) { this.state = state; }

    void pay() { state.pay(this); }
    void ship() { state.ship(this); }
    void confirm() { state.confirm(this); }
}

// 使用：
OrderContext order = new OrderContext();
order.ship();      // 未支付不能发货
order.pay();       // 支付成功
order.ship();      // 发货成功
order.confirm();   // 确认收货成功
```

## 4. 函数式编程对设计模式的影响

```java
// JDK 8 引入 Lambda 后，许多传统设计模式可以被简化

// ┌────────────┬──────────────────────┬──────────────────────────┐
// │ 传统模式    │ 传统实现             │ 函数式简化               │
// ├────────────┼──────────────────────┼──────────────────────────┤
// │ 策略模式   │ Strategy 接口 + 实现   │ Function/Lambda          │
// │ 命令模式   │ Command 接口 + 实现   │ Runnable/Callable        │
// │ 观察者模式 │ Observer 接口 + 实现  │ Consumer/EventHandler    │
// │ 模板方法   │ 抽象类 + 继承         │ 高阶函数 + 组合          │
// │ 装饰器     │ 包装类                │ Function.andThen()       │
// │ 工厂方法   │ Factory 接口 + 实现   │ Supplier/Lambda          │
// └────────────┴──────────────────────┴──────────────────────────┘

// 示例：策略模式用 Lambda
List<String> list = Arrays.asList("B", "C", "A");
list.sort(String::compareTo);  // Comparator 是一个策略接口

// 示例：观察者用 Consumer
button.setOnClickListener(event -> System.out.println("Clicked"));

// 示例：装饰器用 Function.andThen()
Function<String, String> addHeader = s -> "=== " + s;
Function<String, String> addFooter = s -> s + " ===";
Function<String, String> decorated = addHeader.andThen(addFooter);
System.out.println(decorated.apply("Hello"));  // "=== Hello ==="
```

### Q1：工厂方法、抽象工厂、建造者模式的区别？

```java
// 工厂方法：一个工厂创建一种产品
//   场景：Collection.iterator()、URL.openConnection()

// 抽象工厂：一个工厂创建一个产品族
//   场景：不同操作系统下的 UI 组件

// 建造者模式：分步骤创建复杂对象
//   场景：Computer.Builder、StringBuilder

// 简单区分：
// 工厂方法：创建的对象比较"简单"（单个对象）
// 抽象工厂：产品之间有关联性（同一品牌的产品族）
// 建造者：对象复杂，有很多可选项
```

### Q2：策略模式和状态模式的区别？

```java
// 策略模式：
// - 客户端主动选择和切换策略
// - 策略之间是"平级"关系
// - 强调算法的可替换性

// 状态模式：
// - 状态自动切换（状态机）
// - 状态之间有"转移"关系
// - 强调对象行为随状态变化

// 比喻：
// 策略模式：去上班，选择地铁/公交/开车（你主动选择）
// 状态模式：交通灯，红/黄/绿自动切换（状态自动流转）
```

### Q3：代理模式和装饰器模式的区别？

```java
// 代理模式：
// - 控制对目标对象的访问
// - 可以延迟加载、权限控制、日志等
// - 通常和目标对象实现相同接口

// 装饰器模式：
// - 动态扩展功能
// - 可以嵌套多层装饰
// - 也实现相同接口
// - 关注"增强功能"而不是"控制访问"

// 代理模式：房产中介（控制访问、附加服务）
// 装饰器模式：给咖啡加奶加糖（动态扩展功能）
```
