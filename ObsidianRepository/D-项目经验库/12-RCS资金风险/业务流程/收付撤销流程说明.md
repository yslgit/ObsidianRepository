# 收付撤销流程说明

## 一、触发入口（3种途径）

| 入口 | Controller | 核心调用 |
|------|-----------|---------|
| **前端撤销按钮** | `StsControler.doPaymentFlowCancel()` | → `PaymentFlowCisService.doPaymentFlowCancel()` |
| **一键回退** | `BizComControler.doReverseFlow()`（第2步） | → `stsPaymentFlowCisService.doPaymentFlowCancel()` |
| **批量撤销** | 批量处理 | → `PaymentFlowCisService.doPaymentFlowCancel()` |

---

## 二、撤销主流程

**核心类**: `settle.sts/sts-core/.../PaymentFlowProcessServiceImpl.java:1120`

根据 `normalDealStatus` 状态分流：

```
                     doCancel()
                          |
           +--------------+--------------+
           |              |              |
        SD/CP           END          其他状态
           |              |              |
           v              v              v
    dealPaymentFor   dealPaymentFor  dealPaymentFor
    SdOrCp()         End()           Others()
           |              |              |
           |         +-----+-----+       |
           |         |           |       |
           |     cancelDeal   启动审批    |
           |     Status=AW    流程       |
           |         |           |       |
           v         v           v       v
       直接撤销        审批流程       直接撤销
    (不需审批)                     (不需审批)
```

### 状态分流说明

| normalDealStatus | 处理方法 | 是否需审批 | 说明 |
|-----------------|---------|-----------|------|
| SD（发报处理中） | `dealPaymentForSdOrCp()` | 否 | 直接撤销 |
| CP（预处理） | `dealPaymentForSdOrCp()` | 否 | 直接撤销 |
| END（已完成） | `dealPaymentForEnd()` | **是** | 设 `cancelDealStatus=AW`，发起审批 |
| 其他状态 | `dealPaymentForOthers()` | 否 | 直接撤销 |

---

## 三、审批流程

### 3.1 撤销状态流转

```
I(初始) → AW(待审核) → AD(审核处理中) → SW(待发送) → SD(发送处理中) → END(结束)
```

### 3.2 审批流程启动

- **触发条件**: 收付状态为 `END` 时进入 `dealPaymentForEnd()`
- **操作**: `cancelDealStatus=AW` → `doAuditProcessStart()` → `settleEflowService.startEflow("settlePayment", "paymentFlowAuditProcess", ...)`
- **流程定义 key**: `paymentFlowAuditProcess`（`SettleStsConstants.PAYMENTFLOW_AUDIT_PROCESS`）

### 3.3 审批监听

**监听类**: `settle.biz/.../eflow/listener/PaymentFlowAuditServiceImpl.java`

| 审批结果 | 调用方法 | 核心操作 |
|---------|---------|---------|
| **通过** | `PaymentFlowProcessService.doAuditProcessApproval()` | `cancelDealStatus=SW` → 组装撤销报文 → `doMessageSend()` 发送 |
| **拒绝** | `PaymentFlowProcessService.doAuditProcessRefuse()` | 撤销状态回退 |

---

## 四、撤销报文生成链路

```
doAuditProcessApproval()
    → doMessageSend(paymentFlow, user, null)
        → dealPaymentFlowMessage()     [MessageDealServiceImpl:928]
            ├─ cancelFlag=true
            ├─ 查撤销MT类型（如MT292）
            ├─ operateType=CANC
            └─ createMessage()
                → doCancMessageSend()  [BwsBaseCisServiceImpl:157]
                    ├─ 重新生成 pdocId（20场）
                    ├─ 设置 tcsDealStatus=CANCEL
                    ├─ bwsMessageFactory.createMessage()
                    └─ messageSwiftBuilderImpl.buildMessage()
                        ├─ MT292撤销报文体（拼接原报文到79场）
                        └─ ISO模板映射：MT292 → camt.056/camt.058  [BaseBwsCommon:280]
```

### MT292 撤销报文构建关键点

- `MessageSwiftBuilderImpl` (`settle.iface/iface-swift/...`) — 处理以 92 结尾的撤销报文
- `BaseBwsCommon:280` — MT292 的 ISO 模板映射（camt.056 / camt.058）
- 原报文体需拼接 `{C:` 开头的内容到 79 场
